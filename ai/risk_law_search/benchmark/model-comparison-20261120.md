## 2. 모델 선정 기준

1. **한국어 성능** — 한국어가 학습 언어에 포함되어 있거나 한국어로 추가 학습한 모델. 입력이 현장 구어체 한국어("썰다가 베었어요")이고 법령도 한국어다.
2. **인스턴스 자원에 맞을 것** — GPU 10GB 조각과 메모리 24 GiB 안에서 실행 가능. 7B 이상 대형 모델은 제외했다.
3. **로컬 실행·사용 가능한 라이선스** — 외부 API 호출 없이 서버 안에서 실행. 공개 라이선스(MIT 등)로 서비스에 쓸 수 있을 것.
4. **현재 구조와 호환** — PR #44 엔진(sentence-transformers 임베딩 + 키워드 혼합)에 코드 수정 없이 모델 이름만 바꿔 끼울 수 있을 것. 문장 길이 512 토큰 이상 처리.
5. **비교 축이 겹치지 않을 것** — 기준선(현재) / 같은 계열 큰 모델 / 다른 계열 / 한국어 특화 / 재정렬 추가를 각각 하나씩 두어, 무엇이 차이를 만드는지 분리해서 볼 수 있게 했다.

## 4. 테스트 진행 방법

### 4-1. 대상과 자료
- 엔진: PR #44 `ai/risk_law_search/engine.py`를 **수정 없이** 그대로 사용했다.
- 자료: 검색 대상 위험사례 카드 105건, 평가일(2026-11-20) 기준 시행 중인 법령 조각 3,406개(HWPX 9개 문서).

### 4-2. 정답셋 (`gold_v0.json`, 33문항)
- **정상 입력 30문항**: 바닥 미끄러짐, 튀김 화재, 가스 누출, 이륜차 배달, 칼 베임, 육절기·반죽기·제면기, 덤웨이터, 사다리, 배기후드, 락스, 감전, 화상, 중량물, 냉동창고, 소화기 등.
  - 카드 정답: 맞는 카드 ID 목록. 이 중 하나라도 맞으면 적중으로 본다.
  - 법령 정답: 맞는 조문 목록(예: `02:제3조`). 보유 법령에 맞는 조문이 불분명한 5문항은 법령 정확도 계산에서 뺐다(25문항으로 계산).
- **무관 입력 3문항**: "오늘 오후에 매장 회의를 합니다", "메뉴판 디자인을 새로 바꿨어요", "ㅁㄴㅇㄹ". 아무것도 통과시키지 않는 것이 정답이다.
- **정답은 AI 보조 초안이며 담당자 검토 전이다.**

### 4-3. 측정 항목

| 구분 | 항목 | 뜻 |
|---|---|---|
| 위험요인 | 카드 Top-1 / Top-3 | 1순위 / 상위 3개 안에 정답 카드가 있는 비율 (판정 기준점과 무관한 순위 지표) |
| | 카드 MRR | 첫 정답 카드 순위의 역수 평균 (1.0이면 항상 1위) |
| | 선택 결과 적중 / 정밀도 | 실제 analyze 규칙(기준 통과 카드 최대 3개)으로 고른 결과에 정답이 있는 비율 / 고른 카드 중 정답 비율 |
| 법령 | 위험요인별 법령 | analyze에서 1순위 위험요인에 붙는 법령 1개가 정답인 비율 (**서비스 화면에 보일 값**) |
| | 법령 검색 1순위 | search 경로(문서 번호 순서 규칙)의 첫 조문이 정답인 비율 |
| | 조문 순위 Top-1 / Top-3 | 시행 중인 조각 전체를 점수 순으로 정렬했을 때 정답 조문의 위치 |
| 무관 입력 | 통과 / 법령 반환 | 무관 입력에 카드가 기준을 통과한 비율 / 법령이 반환된 비율 |
| 시간 | 준비 시간 | 법령·카드 임베딩 + 카드–법령 연결 계산 (서버 시작 시 1회) |
| | 검색 1건 | 입력 1문장을 처리하는 시간: 검색어 임베딩, 카드 순위, 위험요인별 법령, 조치 항목, 법령 검색, (C5) 재정렬 |
| | 최대 메모리 | 프로세스 최대 사용 메모리 |

### 4-4. 진행 절차
1. 조합마다 별도 프로세스를 띄워 C1 → C2 → C3 → C4 → C5 순서로 실행했다. 서로 영향을 주지 않게 하기 위해서다.
2. 엔진을 만든다. 이때 법령 3,406개와 카드 105건을 임베딩하고, 카드–법령 연결을 계산한다. 여기까지가 준비 시간이다.
3. 33문항마다 한 번 미리 실행한 뒤, 두 번째 실행 시간을 기록했다.
4. 결과는 조합별 JSON(`results_20261120/*.json`)으로 저장했다. 새 파일로만 저장하며 덮어쓰지 않는다.

### 4-5. 공정성을 위해 맞춘 점
- **Chroma 저장소 대신 메모리 색인을 끼워 넣었다.** 점수 계산(벡터 내적)은 원래와 같고, Chroma 패키지가 없는 환경이라 이렇게 했다. 원래 Chroma를 쓰면 준비 시간 중 임베딩 단계는 처음 한 번만 든다.
- **최대 길이는 모두 512 토큰으로 맞췄다.**
- **판정 기준점은 현재 값(e5-small에 맞춘 값)을 그대로 두었다.** 예: 카드 의미 원점수 0.83. 다른 모델에는 불리할 수 있으므로, 기준점과 무관한 순위 지표(Top-1·Top-3·MRR)를 함께 제시한다.
- **C5는 재정렬을 세 군데 모두에 적용했다.** 카드 순위, 법령 순위, 카드–법령 1순위 연결이다.

## 6. 정확도와 속도를 합친 종합 순위

- **종합 점수 = 0.7 × 종합 정확도 + 0.3 × 속도 점수**
- 속도 점수 = (가장 빠른 조합의 검색 1건 평균 시간) ÷ (해당 조합의 평균 시간). 가장 빠른 C1이 1.0이다.
- 비중 70:30은 이번 비교를 위해 정한 값이며 팀 기준이 아니다.

| 종합 순위 | 조합 | 종합 정확도 | 속도 점수 | **종합 점수** | 정확도 순위 | 속도 순위 |
|---|---|---|---|---|---|---|
| **1** | **C1 e5-small (현재)** | 0.748 | 1.000 | **0.824** | 2 | 1 |
| 2 | C3 bge-m3 | 0.737 | 0.165 | 0.565 | 3 | 2 |
| 3 | C4 KURE-v1 | 0.727 | 0.158 | 0.556 | 4 | 3 |
| 4 | C5 bge-m3 + 재정렬 | 0.780 | 0.001 | 0.546 | 1 | 5 |
| 5 | C2 e5-large | 0.680 | 0.120 | 0.512 | 5 | 4 |

### 결과 요약
- **종합 1위는 현재 모델 C1(e5-small)이다.** 정확도는 2위로 1위 C5와 차이가 크지 않다. 그런데 속도는 다른 모델보다 6~960배 빠르다.
- **위험요인 찾기만 보면 C5(재정렬)가 가장 좋다.** 카드 Top-1이 97%로, C1(80%)보다 30문항 중 5문항을 더 맞혔다. 그러나 CPU에서 1건에 약 40초가 걸려 지금 상태로는 서비스에 쓸 수 없다.
- **법령은 모든 모델이 44~56%로 낮다.** 모델을 바꿔도 크게 나아지지 않았다(→ 7-2).
- **큰 임베딩 모델(C2·C3·C4)은 카드 Top-3를 100%로 올렸다.** 그러나 법령 정확도는 오르지 않았고, 준비 시간은 약 9배 늘었다(CPU 기준).

## 7. 나머지 설명

### 7-1. 해석할 때 주의할 점
- **문항 수가 적다.** 정상 입력 30문항이라 1문항이 3.3%p다. 80%·83%·87% 차이는 1~2문항 차이이며, 통계적으로 의미 있는 차이라고 단정할 수 없다. 반면 C5의 카드 Top-1 +17%p(5문항)는 상대적으로 뚜렷하다.
- **정답셋은 AI 보조 초안이고 검토 전이다.** 담당자 검토 후 수치가 바뀔 수 있다.
- **속도는 로컬 CPU 기준이다.** 인스턴스 GPU에서는 큰 모델과 재정렬의 시간이 크게 줄어 종합 순위가 바뀔 수 있다. 특히 C5는 속도 점수가 거의 0이라 순위가 밀렸다. GPU에서 1건이 1초 안팎으로 줄면 종합 1위가 될 수도 있다. **이것은 가설이며 측정하지 않았다.**
- **판정 기준점이 e5-small에 맞춰져 있다.** 다른 모델에서 "선택 결과" 지표가 불리할 수 있다. 그래서 순위 지표(Top-1·Top-3·MRR)를 함께 봐야 한다.

### 7-2. 법령 정확도가 낮은 이유 (관찰과 가설)
- **[관찰]** 서비스 화면에 보일 "위험요인별 법령"은 입력 문장이 아니라 **미리 계산한 카드–법령 연결의 1순위**다. 따라서 위험요인 카드를 맞혀도, 그 카드의 연결이 어긋나 있으면 틀린다. PR README에도 어색한 1순위 연결 4건(식용유 화재 → 액화석유가스법 제56조 등)이 적혀 있다.
- **[관찰]** C5에서 재정렬은 카드 순위를 크게 올렸지만, 조문 순위 Top-1은 44% → 28%로 오히려 떨어졌다.
- **[가설]** 법령 조각은 길고 형식적인 문장이라 512 토큰에서 잘리거나, 구어체 입력과 직접 비교하기 어려울 수 있다. 확인하려면 조문 제목만으로 재정렬하는 방식을 따로 실험해야 한다.
- **[결론]** 법령 쪽은 모델 교체보다 **카드–법령 연결표를 담당자가 검수**하는 것이 정확도에 더 직접적이다.

### 7-3. 무관 입력 처리
- **카드:** 모든 조합에서 무관 입력 3문항을 기준 미달로 처리했다(통과 0%). 이 경우 analyze는 가장 가까운 카드 1개를 `low_confidence`(기준 미달·확인 필요)로 붙인다. 이는 PR 설계대로이며, 정보 부족을 낮은 위험으로 처리하지 않는다.
- **법령 검색:** 일부 무관 입력에 조문이 반환됐다.
  - 예 1: "오늘 오후에 매장 회의를 합니다" → 산업안전보건법 제24조. C2·C3·C4·C5에서 나왔다.
  - 예 2: "메뉴판 디자인을 새로 바꿨어요" → 도로교통법 제80조. C1·C2·K0에서 나왔다.
- 법령 검색에도 카드처럼 절대 기준을 하나 더 두는 개선이 필요하다.

### 7-4. 권장 사항
1. **당분간 현재 모델(e5-small)을 유지한다.** 종합 1위이고, 정확도 차이가 작다.
2. **재정렬은 카드에만, GPU에서 다시 측정한다.** 인스턴스에서 C5를 카드 재정렬만 켜고 측정해, 1건 시간이 서비스 허용 범위(예: 1초) 안에 드는지 확인한다.
3. **법령 정확도는 연결표 검수로 해결한다.** 카드 105건의 1순위 연결을 담당자가 검토하는 편이 모델 교체보다 효과가 크다.
4. **정답셋을 검토하고 늘린다.** 담당자 검토 후 50~100문항으로 늘리고, 음성 전사문 형태 입력도 추가한다.
5. **모델 선택은 팀이 결정한다.** 이 결과는 비교 자료일 뿐이고 모델을 확정한 것이 아니다.

### 7-6. 재현 방법

```
# 저장소 루트에서 (결과 폴더에 같은 이름 파일이 있으면 덮어쓰지 않고 중단)
python ai/risk_law_search/benchmark/bench.py --config C1 --out <결과 폴더>   # K0, C1~C5
python ai/risk_law_search/benchmark/report.py <결과 폴더>                    # 비교 표 출력
```

| 파일 | 내용 |
|---|---|
| `gold_v0.json` | 정답셋 33문항 (AI 보조 · 검토 전) |
| `bench.py` | 측정 스크립트 (PR 엔진 수정 없음, 메모리 색인 사용) |
| `report.py` | 결과 JSON → 비교 표 |
| `results_20261120/*.json` | 조합별 원시 결과 (문항별 상위 3개 카드, 선택 결과, 법령, 시간) |

인스턴스에서 다시 측정하려면 `bench.py`의 `device="cpu"`를 `"cuda"`로 바꾸고, GPU용 torch를 설치한 뒤 실행한다. **이 변경은 아직 실행해 보지 않았다.**
