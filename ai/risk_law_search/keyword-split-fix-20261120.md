# 낱말 나열 입력의 분석 단위 분리 기록 (2026-11-20)

> 상태: 확인용 독립 모듈 개선. 검색 결과는 위험 후보이며 최종 판단은 담당자가 한다.

## 1. 발견한 문제

- 테스트 화면에 "칼 튀김기 선반 바닥"을 넣으면 칼·튀김기 위험요인만 나오고 선반·바닥 위험요인은 나오지 않았다.
- 원인
  1. 띄어쓰기로 나열한 낱말 4개가 한 문장으로 묶여 분석 단위가 1개였다.
  2. 단위당 위험요인은 최대 3개(`MAX_RISKS = 3`)인데, 튀김기 카드 2개(튀김기 폭발, 식용유 화재)와 칼 카드 1개가 3칸을 모두 차지했다.
  3. 동의어 확장(튀김 → 식용유, 칼 → 베임·식칼)이 튀김기·칼 쪽 점수를 더 높였다.

## 2. 확인한 사실

| 확인 | 결과 |
|---|---|
| 선반·바닥 카드가 없는가 | 아니다. 같은 입력에서 FOOD-11-H3(선반 운반)이 7위, FOOD-05-H2(바닥 물 고임)가 8위였다. |
| 낱말 하나씩 넣으면 나오는가 | 나온다. '선반' → FOOD-11-H3, '바닥' → FOOD-05-H2가 1위다. |

## 3. 선택한 방식

| 방식 | 판단 |
|---|---|
| **낱말마다 단위 분리 (선택)** | 등록 기기를 기기마다 한 단위로 보는 기존 방식과 같다. '단위당 1~3개' 규칙을 유지한다. |
| 한 단위 유지, 고르게 선택 | 낱말이 4개 이상이면 여전히 하나가 빠진다. |

## 4. 바꾼 것

| 파일 | 내용 |
|---|---|
| `textindex.py` | `KiwiTokenizer.bare_noun()` 추가. 조사·어미·동사 없이 명사만으로 된 낱말인지 형태소로 판단한다. |
| `engine.py` | `keyword_list()` 추가. `split_units()`가 낱말만 나열한 문장을 낱말마다 한 단위로 나눈다(`keyword: true`, 원문은 `from_text`). `analyze()`에서 낱말 단위는 앞 단위에서 고른 카드를 피한다(모두 나왔으면 1순위 하나). |
| `tests/test_engine.py` | 테스트 1개 추가: 단위 4개 분리, 선반·바닥 카드 포함, 카드 중복 없음, 조사가 있는 문장은 나누지 않음, 쉼표 나열 분리 |
| `README.md` | 분석 단위 규칙과 한계 갱신 |

나누는 기준

- 구분자: 띄어쓰기·쉼표·가운뎃점(·)·빗금(/)
- 형태소 분석(kiwi)이 있으면 모든 낱말이 맨 명사일 때만 나눈다.
- kiwi가 없으면 쉼표로 나열한 경우만 나눈다.

## 5. 결과

| 입력 | 전 | 후 |
|---|---|---|
| 칼 튀김기 선반 바닥 | 단위 1개: 튀김기 폭발, 칼 베임, 식용유 화재 | 단위 4개: 칼(베임) / 튀김기(화재) / 선반(운반 작업) / 바닥(물 고임·미끄러짐) |
| 칼, 튀김기, 선반, 바닥 | 위와 같음 | 위와 같음 |
| 바닥에 물기가 있어요 | 단위 1개 | 단위 1개(변화 없음) |

- 검사: 키워드 방식 단위 테스트 17개 통과. 혼합 방식 테스트 10개는 이 PC에 임베딩·Chroma 패키지가 없어 건너뜀.
- 로컬 서버(127.0.0.1:8020, keyword 모드)에서 같은 입력으로 단위 4개 분리를 확인했다.
- 정답 세트(`benchmark/gold_v0.json`)는 모두 문장 입력이라 벤치마크 수치에는 영향이 없다. 다시 측정하지 않았다.

## 6. 남은 문제

- 두 낱말이 한 개념이어도 나뉜다. 예: '가스 배관' → '가스'·'배관'. '배관' 단위에 '보행 전 장해물 확인' 같은 약한 결과가 섞인다.
- 혼합(임베딩) 방식에서는 직접 확인하지 않았다.
- 낱말 나열 입력을 정답 세트에 넣어 측정하지 않았다.

## 7. 추가: 문장 입력의 절 분리

### 문제

- 낱말 하나('바닥')나 짧은 문장('바닥이 미끄러워요')은 바닥 카드 3개가 나오지만, 여러 작업을 한 문장에 쓰면 빠졌다.
  - '칼로 재료를 손질하고 튀김기로 튀기고 선반에서 물건을 꺼내는데 바닥이 미끄러워요' → 칼 카드 3개만
  - '칼이랑 튀김기를 쓰고 선반에 물건을 올리고 바닥을 청소해요' → 바닥 빠짐
- 원인은 같다. 긴 문장 하나가 단위 1개라 3칸을 앞쪽 위험이 다 차지했다.

### 바꾼 것

| 파일 | 내용 |
|---|---|
| `textindex.py` | `KiwiTokenizer.clause_cuts()` 추가. 나열형 연결 어미 뒤의 위치를 찾는다. 뒤가 보조 용언이면('닦고 있어요') 자르지 않는다. |
| `engine.py` | `clauses()` 추가. 나열형 연결 어미(고·며·으며·는데·은데·지만·거나)에서 절로 나눈다(`clause: true`). 낱말 하나뿐인 조각은 앞 절에 붙인다. 앞 단위에서 고른 카드를 피하는 규칙을 절 단위에도 적용한다. |
| `tests/test_engine.py` | 테스트 1개 추가: 4개 절 분리, 선반·바닥 카드 포함, '~다가'·보조 용언 비분리 |
| `README.md` | 절 분리 규칙과 한계 |

- 나누지 않는 경우: '~다가·~어서'(원인·순서로 한 사건, 예: '칼로 자르다가 칼이 미끄러졌어요'), 보조 용언 앞 '~고', kiwi가 없는 환경

### 결과

| 입력 | 후 |
|---|---|
| 칼로 재료를 손질하고 튀김기로 튀기고 선반에서 물건을 꺼내는데 바닥이 미끄러워요 | 단위 4개: 칼 / 튀김기 / 선반 / 바닥 |
| 칼이랑 튀김기를 쓰고 선반에 물건을 올리고 바닥을 청소해요 | 단위 3개: 칼·튀김기 / 선반 / 바닥 |
| 주방에서 칼, 튀김기를 사용하고 선반과 바닥을 정리합니다 | 단위 2개: 칼·튀김기 / 선반·바닥 |
| 칼로 자르다가 칼이 미끄러졌어요 | 단위 1개(변화 없음) |

정답 세트 30문항(검토 전)에서 analyze 결과로 비교했다. 벤치마크 스크립트는 단위 분리를 쓰지 않아 별도 계산했다.

- 카드 적중률(정답 카드가 하나라도 포함): 0.867 → 0.867(변화 없음)
- 나뉜 문항 3개
  - Q26 '쌀 포대를 들고 계단으로 내려가요': 정답 카드 2개 → 4개(계단 위험 추가)
  - Q15 '덤웨이터 문을 열고 몸을 넣어서 음식을 꺼내요': 정답 4개 + 엉뚱한 카드 2개(문턱 넘어짐, 국물 화상)
  - Q21 '고무장갑을 오래 끼고 설거지해서 손에 습진이 생겼어요': 뒤 절에 넘어짐·떨어짐·감전 카드가 붙음(나누기 전에도 정밀도 0.33)
- 검사: 키워드 방식 단위 테스트 18개 통과. 혼합 방식 10개는 패키지 없음으로 건너뜀.

### 한계

- '~고'가 한 사건의 이어진 동작이어도 나뉜다(Q15, Q21). 뒤 절만으로는 맥락이 약해 엉뚱한 카드가 붙을 수 있다.

## 8. 다음 작업

1. 자주 쓰는 복합 낱말('가스 배관', '냉동 창고' 등)을 나누지 않을지 정한다.
2. 이어진 동작의 '~고'를 나누지 않는 기준(예: 앞 절에 위험 카드가 없을 때만 합침)을 정한다.
3. 낱말 나열·여러 절 문장을 정답 세트에 추가하고, 벤치마크가 analyze 단위 분리를 쓰도록 바꾼다.
4. 혼합 방식 환경에서 같은 입력을 확인한다.
