# 기기·작업 미사용 판정: 정규식에서 형태소 분석으로 (2026-11-23 KST, 로컬)

## 배경

- 사진에 튀김기가 찍혔어도 작업 설명이 "튀김기는 안 써요"이면 튀김(FRY) 평가 행을 만들지 않아야 한다.
- 기존 `retrieval_adapter.py`의 `_FRY_WORK_DENIAL`·`_UNUSED` 정규식은 단어 순서를 그대로 기대한다.
- PR #48 리뷰가 두 번 돌았다. 첫 리뷰에서 "주방에서", 재리뷰에서 "1층 주방에서"·"전기 튀김기"가 빠졌다.
- 장소·수식어·시점·이유·구어 어미가 끼거나 문장부호 없는 음성 전사가 들어오면 패턴을 더해야 했다.

## 방법

- `ai/assessment_authoring/negation.py`: kiwipiepy 0.25.1로 문장을 형태소로 나누고 절 단위로 판정한다.
  1. 연결어미(고·지만·는데·서·며 등)와 종결어미로 절을 나눈다. 문장부호가 없어도 "써요"에서 나뉜다.
  2. 이유 절("고장 나서")이 사용 서술어 없이 끝나면 다음 절까지 본다.
  3. 기기·작업어 뒤에 부정(않·안·못·없·미사용)이 있고, 사이에 다른 명사의 주어·목적어·주제가 없으면 미사용이다.
     않·안·못은 사용 서술어(사용·쓰다·돌리다·가동·켜다·하다·튀기다)가 함께 있어야 한다.
  4. 기기·작업어가 다른 명사를 꾸미기만 하면("튀김기 기름을", "튀김기의 온도") 부정 대상이 아니다.
- `retrieval_adapter.py`: `_affirmed()`·`_positive()`·`text_candidates()`가 이 판정을 쓴다. 정규식 4개를 지웠다.
  튀김 미사용 표시는 튀김 작업어(`튀김`·`튀기`·`튀깁`·`튀겨`)가 미사용으로 진술될 때만 켠다.
- 의존성: `backend/requirements.txt`에 `kiwipiepy==0.25.1`을 추가했다(모델 `kiwipiepy_model` 0.25.0, numpy 함께 설치).

## 3단계 판단: EXAONE 보완 여부

- 남은 실패는 (1) 목록에 없는 동사("꺼 두다", "치우다"), (2) 부정 대상이 기기 부품·대명사("전원을", "그거"),
  (3) 문맥상 부재("메뉴에 없습니다"), (4) 대조 연결("있긴 한데 안 써요"), (5) 생략 주어("저녁에만 써요")다.
- (1)~(4)는 규칙 확장으로 비용 없이 줄일 수 있고, 놓쳐도 사람이 확인하는 쪽이다.
- (5)는 평가 행을 지우는 위험 쪽 오류다. 형태소 규칙만으로는 생략 주어를 안정적으로 복원하기 어렵다.
- EXAONE에 기기별 사용/미사용/불명과 근거 구절을 받는 방식은 (5)에 효과가 있을 수 있다.
  다만 호출이 늘고, 현재 다기기 입력의 출력 한도(502) 문제가 남아 있다.
- 권장(결정 필요): 먼저 "미사용 절 뒤에 주어 없는 사용 절이 이어지면 제외 대신 확인 필요로 둔다"는 보수 규칙을 넣는다.
  실제 음성 전사가 쌓인 뒤 EXAONE 보완 여부를 정한다. 구현은 사용자 결정 후 진행한다.
