## 2. 질의 한 개의 구조

| 필드 | 뜻 |
|---|---|
| `query.text` | 시스템에 줄 질의 문장. 틀 문장은 AI가 썼고, 현장 설명(`site_note`)은 원문 문장 그대로입니다. |
| `query.equipment_ids` | 정답 기기 ID. `equipment_ids_given_to_system=false`인 질의(59개, 동의어 질의)는 ID를 주지 않고 표면형만 줍니다. |
| `gold` | 정답 위험 코드와 근거입니다. 근거에는 출처 ID, 원문 문장, 파일, 쪽이 있습니다. `role`은 둘 중 하나입니다.<br>- `equipment`: 원문이 그 기기의 위험으로 적은 것<br>- `context`: 현장 설명으로 인용한 원문 문장이 더하는 위험 |
| `acceptable_extra_codes` | 다른 출처(v2 인덱스)가 그 기기에 근거를 둔 코드입니다. 너그러운 Precision에서는 오답으로 세지 않습니다. |
| `hard_negatives` | 추천하면 안 되는 함정 후보입니다. 유형, 근거, 신뢰도가 붙어 있습니다. |
| `unverified_master_only` | 기기마스터 v1에만 있고 v2 근거는 없는 코드입니다. 정답도 함정도 아닙니다(판정 보류). |
| `retrieval_v2` | 인덱스 v2로 검색했을 때 정답의 순위입니다. 3가지 모드로 계산했습니다(5절). |
| `leakage`, `eval_exclude` | 정답 출처가 검색 대상에 있는지 표시하고, 질의별로 뺄 출처를 적었습니다. |
| `provenance` | 정답 출처 등급, 기준 출처(`anchor_sources`), AI 보조 범위입니다. |

## 4. 함정 후보(hard negative)

- 조건: 아래 세 가지를 모두 만족할 때만 함정 후보로 둡니다.
  1. 질의 기기에 대한 v2 링크가 0건입니다(실제 사례 출처 포함).
  2. 기기마스터 v1이 그 기기에 그 코드를 적지 않았습니다.
  3. 같은 질의의 정답이 아닙니다.
- 기기마스터에 있는 코드는 함정에서 빼서 `unverified_master_only`로 옮겼습니다(36건).

| 유형 | 건수 | 근거 | 신뢰도 |
|---|---:|---|---|
| `same_source_unattributed` | 16 | 같은 출처(행·쪽)에 함께 적혔지만 기기명이 없는 위험입니다. 현장 설명이 없는 질의에만 붙입니다. 같은 문장을 현장 설명으로 준 질의에서는 정답이 됩니다. | 중간 |
| `confusable_equipment` | 66 | 혼동하기 쉬운 기기에는 등급 A 근거가 있는 위험입니다. 혼동 쌍 24개는 AI 보조로 정했습니다(스크립트 `_PAIRS`). 예: 냉장고↔냉동창고, 칼도마↔채소절단기, 배기후드↔가스레인지 | 낮음 |

- 함정 후보는 모두 82개이고, 52개 질의에 있습니다.
- 다른 두 유형은 규칙만 있고 해당 사례가 없었습니다.
  - `same_source_other_equipment`: 같은 출처에서 다른 기기에 귀속된 위험(0건)
  - `lexical_near_miss`: 기기명이 다른 낱말 안에 든 경우(0건). '알칼리'와 '칼날' 문장에는 위험 코드가 없었습니다. '리프트' 문장의 위험(추락)은 덤웨이터에 근거가 있어 함정이 아닙니다.
- 주의: '근거 0건'은 '실제로 해당 없음'을 증명하지 않습니다.
  - 함정 후보는 검수표에서 사람이 확정해야 합니다.
  - 정의상 인덱스 v2 검색은 함정 후보를 내지 않습니다(검색 결과에 함정 0건).
  - 따라서 함정 후보는 LLM이 더한 후보나 BM25 같은 공출현 검색을 평가하는 데 쓰입니다.

## 5. 검색 순위와 1순위가 아닌 정답

- 순위는 파이프라인의 `R_index_v2`와 같은 규칙으로 계산했습니다.
  - 사례(CASE-*) 출처는 제외합니다.
  - 근거 등급 A를 앞에 두고, 같은 등급에서는 출처가 많은 순서입니다.
  - 여러 기기를 묻는 질의는 코드별로 가장 좋은 등급과 출처 수를 합쳐 정렬했습니다.
- 재현 확인: 42개 기기 모두 파이프라인의 `ranked_codes.json`(R_index_v2)과 순위가 일치했습니다.
- 동의어 질의도 기기 ID가 맞게 해석되었다고 가정하고 계산했습니다.
  - 표면형이 인덱스 v2의 기기 정규식과 맞지 않는 질의는 10개입니다(예: 도어형 세척기, 고기 슬라이서). 이 경우 기기 해석 단계에서 실패할 수 있습니다.

| 모드 | 정답 순위 기준 질의 수 | 1순위 아닌 정답이 있는 질의 | 못 찾는 정답이 있는 질의 | R@3(검색만) | P@3(검색만) |
|---|---:|---:|---:|---:|---:|
| strict_full(제외 없음) | 118 | 82 (69.5%) | 18 | 0.848 | 0.548 |
| leave_source_out(질의별 정답 출처 제외) | 118 | 85 (72.0%) | 36 | 0.759 | 0.508 |
| global_holdout(test 출처 전체 제외) | 118 | 82 (69.5%) | 27 | 0.795 | 0.528 |
| test 분할만, 질의별 제외, 기기 정답만 | 52 | 34 (65.4%) | 8 | 0.840 | - |

- 정답 여러 개 질의(65개) 중 60개(92%)는 일부 정답이 1순위가 아닙니다.
- 기기 정답만 보면(현장설명 정답 제외) 질의별 제외 모드의 비율은 0.661(78/118)입니다.
- R@3·P@3은 정답셋의 난이도를 보여 주는 참고값입니다. 모델 평가가 아닙니다.
  - 정답이 1개인 질의는 P@3의 최대가 1/3입니다.

## 6. 누출 관리

- 정답 출처가 검색 대상에 있는 질의: 114개입니다. 여기서 검색 대상은 v2 링크, v1 구조화표, v1 청크, 기기마스터 근거입니다.
  - 그렇지 않은 9개는 R의 난정·옥계 질의와 P14 질의입니다.
- 분할: test 57개(G 43, R 7, P 7), dev 66개입니다.
  - 같은 출처를 공유하는 G 질의는 한 묶음으로 같은 분할에 둡니다.
  - 묶음은 해시 순서로 test에 넣습니다. 이때 두 조건을 지킵니다.
    1. 인덱스 v2 후보가 있는 기기는 test 출처를 빼도 후보가 1개 이상 남습니다.
    2. test 묶음은 G 질의의 45% 이하입니다.
  - 매장 시나리오는 행이 모두 test 출처일 때만 test이고, 아니면 dev입니다. dev 시나리오 12개는 일부 행이 test 출처와 겹칩니다. dev는 전체 인덱스로 평가하므로 test 평가에는 영향이 없습니다.
- 제외 목록(`holdout제외목록`)의 항목과 효과는 다음과 같습니다.

| 제외 대상 | 수 |
|---|---:|
| v2 링크 출처 | 48 |
| v2 링크 | 118 / 274 |
| v1 구조화표 행 | 18 |
| v1 청크 | 40 / 95 |
| 기기마스터 v1 근거 참조 | 64 |

- 제외 후에도 후보를 모두 잃는 기기는 없습니다.
- v1 청크는 쪽 단위입니다. 그래서 같은 쪽의 다른 행도 함께 빠집니다(부수 제외).
- 누출 등급은 세 가지입니다.
  - 높음(dev, 66개): 정답 출처가 검색 대상에 남습니다. 질의별 `eval_exclude`로 빼면 중간이 됩니다.
  - 중간(test, 48개): 같은 출처는 빠집니다. 같은 문서의 다른 쪽이나 비슷한 문장은 남습니다. 예: D8 p249와 p264는 거의 같은 청크입니다.
  - 낮음(9개): 정답 원문이 검색 대상에 없습니다.
- 기기마스터 v1을 쓰는 방법(R_index, B_rag)은 마스터 근거가 test 출처를 가리키는 경로가 남습니다(64건). 그 방법의 test 점수는 따로 표시해야 합니다.

- 모델로 Recall@K·Precision@K를 측정하지는 않았습니다. 위 수치는 인덱스 v2 검색 순위를 재현한 값입니다.

## 8. 한계

- 실제 기록(R)은 7개뿐입니다. 대부분(G 109개)은 안내서·점검표 문장에서 유도한 정답입니다. 이 정답은 '현장에서 실제로 평가한 위험'이 아니라 '안내서가 그 작업·기기에 적은 위험'입니다.
- 정답 1개 질의가 58개(47%)입니다. 점검표 항목이 대부분 위험 하나만 다루기 때문입니다. 대신 이 질의들에는 현장 설명, 동의어, 함정 후보가 붙어 있습니다.
- 위험 코드는 낱말 규칙으로 붙였습니다. 놓치거나 잘못 붙인 코드가 있을 수 있습니다.
  - 예: D5 '전도' → 넘어짐, 2014 자료 '충돌' → 낙하·충돌.
- 매장 시나리오의 기기 조합, 분식 업종 배정, 혼동 기기 쌍은 AI 보조로 정했습니다. 근거 문장은 원문이지만, 조합 자체는 실제 매장 기록이 아닙니다.
- `context_widen`의 현장 설명은 원문 위험 문장을 그대로 인용합니다. 따라서 설명 안에 위험 낱말이 들어 있습니다. 이 유형은 현장 설명을 쓰는지 확인하는 질의이고, 추론 난이도를 시험하는 질의는 아닙니다.
- 전문가 검수 전입니다. 특히 함정 후보(신뢰도 낮음 66건)와 현장설명 정답 26건을 먼저 검수해야 합니다.
