## 3. 청크 형식

한 줄이 한 청크인 JSONL이다. 쪽 단위로 나눈 뒤 줄 경계에서 최대 900자로 묶었다. 청크끼리 겹치는 부분은 없다.

| 필드 | 설명 |
|---|---|
| `chunk_id` | `문서ID-p쪽-s구간-c순번` (예: `D5-p064-s1-c01`) |
| `doc_id`, `doc_title`, `source_file` | 출처 문서 |
| `pdf_page`, `printed_page` | PDF 쪽과 인쇄 쪽(D5는 PDF−8, D8은 PDF−24로 확인한 경우만) |
| `section`, `topic` | 원문 소제목을 기준으로 붙인 구간명과 주제 |
| `extraction_method`, `needs_visual_check` | 추출 방법, OCR 여부 |
| `matched_accident_terms`, `matched_work_terms` | 고정 단어 목록 중 본문에 그대로 있는 단어(분류 판단 아님) |
| `char_count`, `text_sha1`, `text` | 글자 수, 공백 제거 후 해시, 본문 |

## 4. 구조화 표 형식

- 출처 1: `음식점업 자율안전점검표.pdf`의 점검항목 173개(위험성평가 5, 프로그램 1, 분야별 167).
- 출처 2: `261113_restaurant_completed_assessments_DR/261113_실제사업장_위험성평가사례_8건_DR.jsonl`의 8건. 원본 PDF 쪽에서 원문 문장을 다시 옮겼다.
  - S01(노인인력개발원 자료) p15–20은 이미지형 쪽이다. 기존 렌더링 PNG(`사업단_page15~20.png`)를 보고 전사했다.
  - S02(난정평화교육원) p42–43은 pdftotext로 추출했다.
  - 기존 JSONL의 `hazard_summary`·`control_summary`는 AI 요약이다. 원문 문장으로 쓰지 않았다.
- 원문에 있는 내용만 넣었다. 원문에 없으면 `null`이다.

| 필드 | 점검표 행 | 사례 행 |
|---|---|---|
| `work_or_object` | 점검표 섹션 제목(대부분 설비·작업 대상) | `null`(원문에 작업명 없음) |
| `hazard_text` | 없음 | 원문 유해위험요인 문장 |
| `hazard_terms_in_text`, `accident_type_terms_in_text` | 원문에 그대로 있는 단어 | 원문에 그대로 있는 단어 |
| `current_control` | `null` | `null`(원문에 현재조치 칸 없음) |
| `improvement_measure` | `null` | 원문 권고의견·감소대책 |
| `checklist_control_item` | 점검항목 원문 | `null` |
| `source_text`, `source_pdf_page`, `source_file` | 원문 문장과 출처 | 원문 문장과 출처 |

- 점검표 항목은 갖춰야 할 조치 상태를 묻는다. 현재조치인지 개선대책인지는 사업장 응답(네/아니요)으로 정해진다. 그래서 `checklist_control_item`에만 넣었다.
- 점검표 줄바꿈 처리: pypdf는 실제 띄어쓰기가 있는 줄 끝에 공백을 남긴다. 줄 끝 공백이 있으면 띄우고, 없으면 붙였다(예: `안`+`전하고` → `안전하고`).

## 7. 재현 방법

스크립트의 경로는 이번 작업의 임시 폴더를 가리킨다. 재실행 시 `SC` 경로를 바꾼다.

1. `pdftotext -enc UTF-8 <pdf> raw/<n>.txt` (RAG용 PDF 8개, 파일명 정렬 순서 1–8)
2. `pdftotext -enc UTF-8 -layout <pdf> txt/<n>.txt` (쪽 수 확인용)
3. `powershell -File scripts/ocr.ps1 -Pdf <D5 pdf> -From 58 -To 73 -OutDir ocr5`
4. `python scripts/build_chunks.py` → 청크 JSONL
5. `python scripts/build_table.py` → 구조화 표 JSONL
6. `python scripts/build_law.py` → 법령 검증 목록(조문은 law.go.kr에서 복사해 스크립트에 넣었다)
7. `python scripts/qa.py` → 점검 결과 JSON

## 8. 한계와 다음 작업

- 이 자료는 AI가 추출·전사·요약했다. 안전 전문가 검수 전이다. 현장 안전 성능을 뜻하지 않는다.
- OCR 청크(D5)에는 오인식이 남아 있다. 표시는 했지만 교정하지 않았다.
- D8 표는 텍스트 추출 시 열 순서가 섞인다. 위험요인과 예방대책의 행 대응은 청크에서 보장되지 않는다.
- 구조화 표에는 D5(작업–위험요인–개선대책 형식)와 D8 업종별 표를 넣지 않았다. 과제가 지정한 출처(점검표, 사례 8건)만 사용했다. D5·D8 표를 구조화하려면 쪽 이미지 대조가 필요하다.
- `matched_*_terms`는 고정 단어 목록과 일치하는 단어다. 분류 결과가 아니다.
- D5에서 시각 대조하지 않은 쪽은 OCR 검색만 했다. 놓친 법령 인용이 있을 수 있다.
- 공유 권한: 공개 자료이나 모델 학습·재배포 허락은 확인하지 않았다(사례 8건은 기존 출처검증 파일 기준 `usage_limit` 동일).
- 권장 후속 작업:
  1. D5 음식업 11개 작업 표를 시각 대조해 구조화 표에 추가한다.
  2. 법령 검증 목록 중 해석이 들어간 항목(규칙 제3·4·30조, 제133조 적용 범위, 제673조 주체)을 전문가가 확인한다.
  3. 청크 형식이 확정되면 임베딩·벡터DB를 선택하고 검색 평가 질의를 만든다.
