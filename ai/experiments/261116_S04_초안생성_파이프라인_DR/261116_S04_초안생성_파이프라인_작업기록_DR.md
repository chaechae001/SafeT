## 1. 요약

- S04 초안 생성을 8단계 파이프라인으로 구현했다. 입력 정규화 → BM25 검색 → 위험 항목 생성 → 신호·판단 이유 → 검증 법령 연결 → 현재 조치 후보 → 빨강·노랑 추천 대책 3개 → 스키마 검증.
- 각 단계가 끝나면 진행률 이벤트(20·40·60·80·100%)를 낸다. 100%는 응답 파일 저장 성공 뒤에만 낸다. 프로토타입은 백엔드 저장 대신 로컬 파일 저장을 쓴다.
- TC01 입력 하나로 **7개 항목**이 나왔고 응답 스키마를 통과했다(Draft 2020-12, 형식 검사 포함).
- 모델 엔드포인트와 모델 ID를 확인하지 못했다. 그래서 모델 없이 동작하는 `offline_template` 모드로 실행했다. LLM 호출 코드는 있으나 실제 호출은 하지 않았다.
- 신호 판단기준(C1~C8)이 확정되지 않았다. 안내서 예시를 **임시로** 적용하는 모드와, 모두 `off(criteria_not_set)`로 두는 `strict` 모드를 설정값으로 분리했다.

## 3. 실행 방법

작업 폴더(`261116_S04_초안생성_파이프라인_DR/`)에서 Git Bash로 실행한다. `uv`가 임시 환경에 `jsonschema` 등을 설치한다. 프로젝트에 의존성을 추가하지 않는다.

```bash
bash run_all.sh
```

TC01 한 건만 실행:

```bash
PYTHONIOENCODING=utf-8 uv run -q --with jsonschema==4.* --with referencing --with rfc3339-validator --with rfc3987 python src/run_s04.py --request inputs/tc01_request.json --out runs/tc01_offline_provisional
```

모델 연결 후(엔드포인트·모델 ID 확인 필요):

```bash
SAFET_LLM_BASE_URL=<확인된 URL> SAFET_LLM_MODEL=<확인된 모델 ID> SAFET_LLM_API_KEY_FILE=../serverless_api_key.txt PYTHONIOENCODING=utf-8 uv run -q --with jsonschema==4.* --with referencing --with rfc3339-validator --with rfc3987 python src/run_s04.py --request inputs/tc01_request.json --out runs/tc01_llm --mode llm
```

- 키는 환경 변수나 파일 경로로만 읽는다. 키 값은 로그·출력에 쓰지 않는다. 실행기는 끝날 때 출력 파일에 키 문자열이 있는지 검사한다.
- 실행 환경(확인): Python 3.13.13, jsonschema 4.26.0, uv 0.11.17, Windows 11.

## 5. 설계

### 5.1 단계와 진행률

| 순서 | 처리 | 진행률 이벤트 |
|---|---|---|
| 1 | 요청 스키마 검증, 문장 분리(현장 설명·전사문·사진 장소), 기기 이름 분해(`칼·도마` → 칼, 도마) | 20 `analyze_input` |
| 2 | BM25 검색(문자 2-gram), 위험 항목 생성 | 40 `generate_items` |
| 3 | 신호·판단 이유, 검증 법령 연결, 현재 조치 후보 | 60 `judge_signal` |
| 4 | 빨강·노랑 추천 대책 3개, 응답 스키마 검증과 항목 수리 | 80 `recommend_measures` |
| 5 | 응답 파일 저장 성공 | 100 `save_draft` |

### 5.2 생성 모드

| 모드 | 항목 생성 | 상태 |
|---|---|---|
| `offline_template` | 기기·문장 키워드가 맞는 임시 템플릿 7개 + 템플릿에 없는 문장은 범용 항목(신호 off) | 실행함 |
| `mock_llm` | 저장된 모의 응답을 LLM 경로로 처리 | 실행함(파싱·필터 검사용) |
| `llm` | OpenAI 호환 엔드포인트 호출. 다중 질의 검색 결과와 검증 법령 후보를 프롬프트에 넣음 | **미실행**(엔드포인트 미확인) |

### 5.3 안전장치

- 법령: 검증 목록(`verification_status=검증`)의 조항만 붙인다. 오프라인 모드는 (1) 검색된 청크가 그 조항을 인용하고 (2) 템플릿 후보에 있는 조항만 붙인다. LLM 모드는 검색 청크가 인용한 검증 조항 키 중 모델이 고른 것만 붙인다. 미검증 8건은 쓰지 않는다.
- 현재 조치 후보·추천 대책: 구조화 표의 점검표 행 문장을 그대로 쓴다(`cm-<row_id>`, `rm-<row_id>`로 출처 추적). 사례 행(CASE-*)은 비교 대상이라 원천에서 뺐다.
- 사용자 필드: 현재 조치 선택, 대책 체크, 담당자·예정일, 예상 신호는 만들지 않는다. 화면은 미선택·미체크·빈 값으로 시작한다.
- 스키마 위반 항목은 `off(invalid_output)`로 바꾸고 계약 밖 키를 버린다.
- `criteria_version`은 팀 확정 전이라 항상 null이다. 임시 기준은 `basis.matched_rules`(`PROVISIONAL.guide13.*`)와 판단 이유 앞의 `[임시 기준·전문가 확인 필요]`로 표시한다.
