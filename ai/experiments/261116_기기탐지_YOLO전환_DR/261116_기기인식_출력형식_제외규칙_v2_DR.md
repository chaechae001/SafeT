## 1. 처리 흐름

| 단계 | 담당 | 내용 |
|---|---|---|
| 1 | 백엔드 | 사진을 EXIF 회전 적용 후 탐지 서버에 보낸다. |
| 2 | 탐지 모델 | 원 클래스(또는 프롬프트)와 점수, 박스를 낸다. |
| 3 | 탐지 서버 | 대응표(`class_map_version`)로 원 클래스를 `equipment_id`로 바꾼다. 대응 없으면 `null`. |
| 4 | 백엔드 | 3절 규칙으로 걸러 `ai_found[]`를 만든다. |
| 5 | 화면 | S03 '사진에서 새로 찾은 기기'에 체크박스로 보여준다. |

## 2. 출력 필드

| 필드 | 필수 | 뜻 |
|---|---|---|
| `detections[].equipment_id` | 예 | 기기 마스터 ID. 대응 없으면 `null` |
| `detections[].confidence` | 예 | 탐지 점수 0–1 |
| `detections[].bbox` | 예 | `[x0, y0, x1, y1]` 0–1 정규화 |
| `detections[].photo_id` | 예 | 근거 사진. `detection_refs`는 `photo_id#detection_id` |
| `detections[].detector_class` | 예 | 탐지기 원 클래스명 또는 프롬프트 |
| `detections[].class_map_match` | 아니요 | `direct`, `partial`, `finetuned`, `open_vocab` |
| `detector.*` | 예 | 탐지 모델 버전 추적 정보 |
| `status`, `photos[].status` | 예 | v1과 같음 |

## 3. 등록 기기 제외와 ai_found 생성 규칙

v1 규칙 R1–R8을 유지한다. 탐지 모델 때문에 추가·변경한 규칙은 굵게 표시했다.

| 순서 | 규칙 | 제외 사유 코드 |
|---|---|---|
| R1 | `master_version` 또는 **`class_map_version`**이 백엔드와 다르면 결과 전체를 쓰지 않는다. 인식 실패로 처리한다. | `master_mismatch`, **`class_map_mismatch`** |
| R2 | `equipment_id`가 `null`이거나 마스터에 없으면 화면에 내지 않는다. | `unmapped` |
| **R2a** | **대응표에서 `detection_target`이 `no` 또는 `hold`인 기기는 화면에 내지 않는다(예: 이륜차, 전기설비).** | **`not_detection_target`** |
| **R2b** | **`class_map_match=partial`인 결과는 기본 제외한다. COCO `oven`→가스레인지처럼 다른 기기와 구분하지 못하기 때문이다. 쓸지는 평가 후 기기별로 정한다.** | **`partial_mapping`** |
| R3 | `confidence`가 임계값 T 미만이면 제외한다. T는 미정이며 **기기별로 다를 수 있다**. 평가 후 정한다. | `below_threshold` |
| R4 | 같은 `equipment_id`는 박스·사진이 여러 개여도 하나로 합친다. `detection_refs`는 T 이상 검출을 모두 담는다. 대표 신뢰도는 최댓값이다. **같은 기기 여러 대도 S03에는 한 줄로 보인다.** | (합침) |
| R5 | 사업장 기기에 `source=db`로 같은 `equipment_id`가 있으면 제외한다. | `registered_db` |
| R6 | `source=manual` `custom_name`이 표준명·표준명 부분·동의어와 맞으면 제외한다(v1과 같은 정규화). | `registered_manual_name_match` |
| R7 | R6에서 한 이름이 여러 항목과 맞으면 모두 제외한다(제안). | `registered_manual_ambiguous` |
| R8 | 남은 항목만 `ai_found[]`에 넣는다. `selected` 기본값 `true`. | — |

화면 상태(실패와 '새 기기 없음' 구분), 늦게 온 결과 병합, 저장 범위는 v1 3.1–3.3절과 같다.

## 4. 결정이 필요한 사항

| 번호 | 내용 | 현재 처리 |
|---|---|---|
| Q1 | 임계값 T(기기별 허용 여부 포함) | 미정 |
| Q2 | 부분 대응 결과 사용 여부(R2b) | 제안: 기본 제외 |
| Q3 | 탐지 모델·라이선스 선택(AGPL-3.0 포함) | 전환계획 3·4절 참고 |
| Q4 | 탐지 박스를 VLM 상태 관찰에 넘길지 | 제안: `detection_refs`로 전달 |
| Q5 | v1의 업종 밖 기기 표시, 모호한 직접 추가 이름 처리 | v1과 같음, 미정 |

## 5. 평가 방법

- 1차: 이미지 단위. 탐지 결과에 R2–R4를 적용해 이미지별 `equipment_id` 집합을 만든다. 평가셋(사람 검수 후)과 비교해 기기별 정밀도·재현율을 낸다.
- 2차(박스 라벨 완성 후): 박스 단위 mAP·IoU. 지금 박스는 격자 근사라서 쓰지 않는다.
- (a) 사전학습, (b) 오픈 어휘, (c) 파인튜닝을 같은 사진·같은 규칙으로 비교한다. `detector`, `class_map_version`, T를 결과와 함께 남긴다.
- 한계는 v1과 같다: 치킨 사진뿐, 튀김기 편중, 같은 장면 사진 다수, 사진 권한 미확인. 점수는 현장 성능이 아니다.

## 6. VLM 상태 관찰과의 경계

- 이 형식은 '무엇이 있나'만 다룬다. 물기·적재·기름때 같은 상태는 VLM 출력에서 다룬다.
- VLM이 기기 주변 상태를 판단할 때 `detection_refs`와 박스를 입력으로 받을 수 있다. 상태 관찰 형식은 해당 트랙에서 정한다.
