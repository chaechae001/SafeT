# S03 사진 기기 인식 출력 형식과 등록 기기 제외 규칙 (v1 초안)

- 작성일: 2026-11-16 (Asia/Seoul)
- 작성: DR (Claude 보조)
- 상태: 초안. 팀 검토 전. 모델은 실행하지 않았다.
- 화면 근거: 화면설계서 v3.19 9쪽(B02), 14쪽(S03), 34쪽(데이터 필드)
- 관련 파일: `schemas/261115_기기인식_출력.schema.json`, `schemas/261115_기기인식_출력.example.json`, `261115_기기마스터_v1_DR.json`

## 1. 처리 흐름

| 단계 | 담당 | 내용 |
|---|---|---|
| 1 | 백엔드 | 현장 사진(photo_id)과 기기 마스터 버전을 모델에 보낸다. |
| 2 | 비전 모델 | 사진마다 보이는 기기를 마스터 `equipment_id`로 낸다. 신뢰도와 영역을 함께 낸다. |
| 3 | 백엔드 | 마스터 대조, 임계값 적용, 사진 간 합치기, 등록 기기 제외를 한다. |
| 4 | 백엔드 | 남은 기기로 `ai_found[]`를 만든다(34쪽: `equipment_id`, `detection_refs[]`, `selected`). |
| 5 | 화면 | S03 '사진에서 새로 찾은 기기'에 'AI 인식' 표시와 체크박스로 보여준다. |

모델은 사업장 등록 기기를 몰라도 된다. 제외는 백엔드가 한다. 그래야 모델 출력을 평가셋으로 그대로 채점할 수 있다.

## 2. 모델 출력 형식

전체 형식은 JSON 스키마 파일을 따른다. 핵심 필드는 아래와 같다.

| 필드 | 필수 | 뜻 |
|---|---|---|
| `status` | 예 | `ok`, `partial`(일부 사진 실패), `failed`, `no_photo` |
| `master_version` | 예 | 인식에 쓴 마스터 버전 |
| `model_version`, `judged_at` | 예 | 추적용. 34쪽 신호 필드와 같은 방식 |
| `photos[].status` | 예 | 사진별 `analyzed` / `failed` |
| `detections[].equipment_id` | 예 | 마스터 ID. 마스터에 없으면 `null` |
| `detections[].confidence` | 예 | 0–1 점수 |
| `detections[].bbox` | 예 | `[x0, y0, x1, y1]` 0–1 정규화. EXIF 회전 적용 화면 기준. 없으면 `null` |
| `detections[].raw_label` | 아니요 | 모델이 본 이름. 로그용 |
| `detections[].evidence_note` | 아니요 | 판단 근거 한 줄 |

`detection_refs`는 `photo_id#detection_id` 형식으로 만든다. 사용자가 근거 사진과 영역을 다시 볼 수 있게 한다.

## 3. 등록 기기 제외와 ai_found 생성 규칙

규칙은 위에서부터 차례로 적용한다. 제외한 항목은 `excluded[]`에 사유와 함께 남긴다.

| 순서 | 규칙 | 제외 사유 코드 |
|---|---|---|
| R1 | 응답 `master_version`이 현재 마스터와 다르면 결과 전체를 쓰지 않는다. 인식 실패로 처리한다. | `master_mismatch` |
| R2 | `equipment_id`가 `null`이거나 마스터에 없으면 화면에 내지 않는다. S03에는 직접 추가가 없기 때문이다(14쪽 04). | `unmapped` |
| R3 | `confidence`가 임계값 T 미만이면 제외한다. T는 정하지 않았다. 평가셋 결과로 팀이 정한다(5절). | `below_threshold` |
| R4 | 같은 `equipment_id`는 사진이 달라도 하나로 합친다. `detection_refs`는 T 이상인 검출을 모두 담는다. 대표 신뢰도는 최댓값이다. | (합침) |
| R5 | 사업장 기기에 `source=db`로 같은 `equipment_id`가 있으면 제외한다. | `registered_db` |
| R6 | 사업장 기기의 `source=manual` `custom_name`이 마스터 항목 이름과 맞으면 제외한다. 비교 대상은 표준명, 표준명을 `·`로 나눈 각 부분, 동의어다. 비교 전에 앞뒤 공백 제거, 연속 공백 1칸, 영문 소문자로 맞춘다. | `registered_manual_name_match` |
| R7 | R6에서 한 `custom_name`이 여러 항목과 맞으면 그 항목들을 모두 제외한다. 중복 표시보다 누락이 덜 혼란스럽다고 보았다. 이 판단은 검토가 필요하다. | `registered_manual_ambiguous` |
| R8 | 남은 항목만 `ai_found[]`에 넣는다. `selected` 기본값은 `true`다(14쪽 02: 처음엔 체크). | — |

### 3.1 화면 상태 규칙

| 상황 | `recognition_state` | 화면 |
|---|---|---|
| 사진 없음 | `no_photo` | 새로 찾은 기기 영역을 비우고 등록 기기만으로 진행. "사진이 없어 기기를 찾지 않았어요" 같은 문구 |
| 호출 실패·전체 실패·R1 | `failed` | 영역을 비움. 실패 사실을 표시. "새로 찾은 기기가 없어요"를 쓰지 않는다 |
| 일부 사진 실패 | `partial` | 성공한 사진의 결과만 표시. 일부 사진을 분석하지 못했다고 함께 표시 |
| 성공, 남은 기기 없음 | `success` | "사진에서 새로 찾은 기기가 없어요"(14쪽 예시 문구) |
| 성공, 남은 기기 있음 | `success` | 체크박스 목록 |

14쪽은 "인식 실패를 인식 성공으로 표시하지 않습니다"라고 정한다. 그래서 실패와 '찾은 기기 없음'을 다른 상태로 둔다.

### 3.2 늦게 온 결과 병합

- 사용자가 해제한 항목은 늦게 온 결과가 다시 체크하지 않는다(14쪽 02).
- 늦게 온 결과에 새 `equipment_id`가 있으면 목록 끝에 `selected=true`로 붙인다. 이 동작은 설계서에 없다. 제안이다.
- 이미 있는 항목은 `detection_refs`만 더한다. 체크 상태는 바꾸지 않는다.

### 3.3 저장

- 저장 범위는 현재안(이번 평가표에만 포함)을 따른다. `261115_AI출력계약_신호기준_DR` 5.3절과 같다.
- 모델 원 응답, `excluded[]`, 임계값 T, `master_version`을 함께 남긴다. 나중에 오인식 원인을 추적하기 위해서다.
- S04 요청에는 `selected=true`인 항목만 `origin=ai_found`로 넘긴다.

## 5. 평가 방법 (모델 실행 시)

- 대상: `261115_기기인식_평가셋_v1_DR.json` 34장. 라벨은 AI 보조 라벨이며 사람 검수 전이다. 검수 후 점수만 공식 수치로 쓴다.
- 기본 단위: 이미지 단위 멀티라벨. 기기별 정밀도(precision)와 재현율(recall)을 낸다. 정밀도는 '찾았다고 한 것 중 맞은 비율', 재현율은 '실제 있는 것 중 찾은 비율'이다.
- 정답 기준: `visibility=clear` 라벨. `partial` 라벨과 `uncertain_candidates`는 따로 센다. 놓쳐도 감점하지 않는 '판정 보류'로 둔다.
- 영역: 라벨 영역은 3x3 격자 근사다. 영역 정확도 지표(IoU)로 쓰기에는 거칠다. 쓰려면 정밀 박스 라벨을 새로 만들어야 한다.
- 제외 규칙 시험: 사진마다 가상 등록 기기 목록(빈 목록, 일부, 전체, 직접 추가 이름 포함)을 만들어 R5–R7 결과를 확인한다.
- 한계: 34장 중 튀김기 사진이 많다. `scene_group`이 같은 사진은 독립 표본이 아니다. 치킨 외 업종 사진은 없다. 점수를 현장 성능으로 말하지 않는다.
- S03 화면 특성상 오인식(없는 기기를 찾음)은 사용자가 해제해야 하는 부담이 된다. 누락은 사업장 관리에서 추가해야 한다. 두 오류의 비용을 팀이 정한 뒤 T를 고른다.
