## 3. 변환 규칙

- 업종 근거 유형은 세 가지다. `업종근거`: D8 해당 업종 절에 명시. `공통근거`: 업종 구분 없는 음식점 자료(CHK·D5·사례)에 있음. `제안`: 그 업종 근거 없음.
- 업종 대응: 치킨→D8 치킨, 카페→D8 커피, 한식→D8 한식. 분식은 대응 절이 없다. 그래서 분식은 `업종근거`가 0개다. 기타는 공통 자료만 쓴다.
- 기기 항목 자체에 문서 근거가 없으면 `evidence_status=제안`이다(9개). 위험요인 단위로도 근거 유무를 표시했다.
- 칼·도마는 화면설계서 S03 예시처럼 한 항목으로 묶었다. 반죽기는 9쪽에서 치킨 '직접 추가' 예시이므로 치킨 목록에 넣지 않았다.
- 소화기·가스경보기는 기기가 아니라 대책이라서 뺐다. 작업대·세제·청소기 등 제외 판단은 JSON `excluded_candidates`에 남겼다.

## 4. 평가셋 라벨링 방식

- 대상: `실제사진/`의 이미지 34장 전부. 원본은 읽기만 했다. zip 파일은 폴더 백업으로 보여 제외했다.
- `image_id`는 파일명에서 확장자를 뺀 값이다. `label_id`는 `image_id#Lnn`이다.
- Claude가 축소본(긴 변 1100px)에 3x3 격자를 그려 보고 라벨을 붙였다. 판단이 어려운 곳은 원본을 잘라 다시 봤다. 축소본은 임시 폴더에만 두었다.
- 영역은 EXIF 회전을 적용한 화면 기준 격자 칸이다. `bbox_norm_from_grid`는 칸을 합친 근사 박스다.
- 판독이 어려운 기기는 라벨에 넣지 않고 `uncertain_candidates`에 두었다(12건). 마스터에 없는 물체는 `not_in_master`에 두었다.
- 출처: 지자체·언론 이미지 16장은 `261113_공개주방_이동파일목록_DR.json`의 URL과 매장명을 옮겼다. 유튜브 프레임은 파일명의 영상 ID로 URL을 재구성했다. 접속 확인은 하지 않았다. 나머지(PotPlayer·brave·브랜드 이미지)는 원 출처를 확인하지 못했다.
- 권한: 34장 모두 '공유 권한 미확인'이다. 인물 노출과 상호·브랜드 노출을 이미지별로 적었다. 학습에 쓰지 않는다고 명시했다.

## 5. 검증 결과

실행: `python 261115_기기마스터_인식평가셋_DR/scripts/validate.py` (jsonschema는 임시 폴더에 설치해 사용). 24개 검사가 모두 통과했다.

- 마스터: ID 중복·형식, 출처 키, 위험요인 코드, 업종근거→D8 출처, 업종 목록↔마스터 일치, 이름·동의어 충돌 없음(제외 규칙 R6 대조용).
- 평가셋: `image_id` 집합 = `실제사진/` 이미지 파일명 집합(34=34), 파일 sha256 일치, `label_id` 중복 없음, 라벨 기기 ID가 마스터에 있음, 격자 형식.
- 원본 보존: 기존 이동파일목록에 sha256이 있는 16장이 그대로임을 확인.
- 스키마: 예시 응답이 스키마를 통과. 잘못된 `status`는 거부됨.
