# RAG 법령 매칭 정답셋·평가 작업기록 (2026-11-22)

- 실행 위치: 로컬 PC(CPU, Python 3.11.9, 추가 패키지 없음). Cloud 실행 없음.
- 범위: 위험요인 ID(카탈로그 `CATALOG-MVP-1.1` 시나리오 26개) → 보유 법령 원문(`chroma/laws` HWPX 9개) 조문 매칭.
- 상태: 정답셋은 **AI 보조 정답·담당자 검토 전**이다. 검색 결과는 후보이며 법령 적용 판단이 아니다.

## 1. 현재 상태 확인

| 경로 | 법령 연결 방식 | 확인 결과 |
|---|---|---|
| 서비스 `authoring_rag_v1` | `retrieve_with_evidence(legal_registry=...)` | `backend/services/authoring_rag.py`가 `legal_registry`를 넘기지 않는다. 법령 후보는 항상 0건이다. 근거는 RAG 인덱스 v2 문장(KOSHA·안내서)과 카탈로그 `source_refs`뿐이다. |
| `ai/risk_law_search` (독립 확인용) | 입력 문장 → 카드 → 법령(A·B·C 경로) | 서비스와 연결되지 않았다. 정답셋 `gold_v0`(입력 문장 30건, AI 보조·검토 전)으로 평가했다. |
| 기존 지표 0.619 / 0.750 | 기기 → 위험 코드 재현율 | 위험요인 추천 지표다. 법령 조문 매칭 지표가 아니다. |

## 2. 정답셋 `261122_RAG_법령정답셋_v1_DR.json`

만드는 법: `law_gold_spec.json`(조문 번호와 근거 유형만 기록) → `build_law_gold.py`가 HWPX 원문에서 법령명·시행본·조문 제목·발췌·항 ID를 채운다. 원문에 없는 조문이나 쪽이 맞지 않는 인용이 있으면 빌드가 실패한다.

| 항목 | 값 |
|---|---|
| 위험요인 | 26개 중 평가 15개, `미확인` 11개 |
| core 조문 | 30개. 그중 출처 문서 직접 인용(`source_cited`) 6개 |
| 분할 | 시나리오 ID 해시 고정 분할. dev 7개, holdout 8개 |
| 원문 | 법령 HWPX 9개(파일 SHA-256 기록), 법령검증목록 v1(law.go.kr, 2026-11-15 조회) |

근거 유형

| 유형 | 뜻 | 해당 위험요인 |
|---|---|---|
| `source_cited` | 카탈로그 source_refs의 문서 B(=RAG 청크 D5) 쪽이 조문을 직접 인용. 법령검증목록 `cited_in` 청크와 쪽 번호로 자동 대조 | ENV(제3·4조), MIX(제92조), LIFT(제86·133조), DELIVERY(제673조) |
| `ai_proposed` | AI가 조문 원문을 읽고 제안. 원문 존재·문구만 확인 | 나머지 core |
| `prior_gold_v0` | 기존 `gold_v0`에도 같은 위험 문장의 정답으로 있음 | 표기된 조문 |

`미확인` 11개: TRANS, KNIFE, KNIFE_STORAGE, RICE, KETTLE, FRY, GRIDDLE, OVEN, SERVE, WASH, CHEM. 예: 제254조(화상 등의 방지)는 용광로 등 다량 고열물 작업 조문이라 주방 화상 적용 여부가 불명하다. 제236조는 인화점 250℃ 미만 액체 대상이라 식용유 적용 여부가 불명하다. 조문을 창작하지 않고 비워 두었다.

## 3. 평가 방법

- 스크립트: `eval_law_matching.py` (재현: `python ai/experiments/261122_RAG_법령매칭_DR/eval_law_matching.py`, 약 4초).
- 질의: 카탈로그 `title + task + event + scenario`. R4·R5만 `keywords + controls[].current_text`를 더한다.
- 지표(조문 단위 상위 10개): recall@k(core), hit@3, MRR(첫 core), exact@1(1순위가 core), acc_p@5(상위 5개 중 core·related 비율).
- 보조 평가: `gold_v0` 입력 문장 25건(법령 정답 있는 것). 질의 확장 없음.

검색기(모두 실행 전에 설정을 정했다. 결과를 보고 조정한 값은 없다)

| ID | 내용 |
|---|---|
| R0 | 서비스 현재. 법령 후보 0건 |
| R1 | 기존 `risk_law_search` 키워드 경로 재현: 항 단위 TF-IDF, 벌칙 감점, 조문별 최댓값. 단, kiwipiepy가 없어 정규식 토큰을 썼다 |
| R2 | 청킹 변경: 조문 단위 BM25, 조문 제목·장절 제목 3배 가중 |
| R3 | R2 + 메타데이터 필터: 문서 01(위험성평가 지침)·04(중대재해처벌법)·05(식품위생법), 목적·정의·벌칙 등 일반 조항 제외 |
| R4 | R3 + 질의 확장(카탈로그 키워드·조치 문구) |
| R5 | R4 + 재순위(원 질의와 조문 제목 토큰이 겹치면 가점) |

해석

- 서비스는 현재 법령 조문을 하나도 연결하지 않는다(R0). 어떤 검색기를 붙여도 0에서 오른다.
- 위험요인 ID 질의에서는 R5가 전체 MRR 0.659 → 0.800, exact@1 0.533 → 0.733으로 가장 높다.
- 다만 dev에서는 R5가 R1보다 낮고(MRR 0.571 < 0.657) holdout에서만 높다. 15건이라 차이가 안정적이지 않다. 직접적인 성능 향상으로 단정하지 않는다.
- 사용자 입력 문장(gold_v0)에서는 조문 단위 BM25 계열이 R1보다 낮다. 구어체 짧은 문장에는 항 단위 TF-IDF가 낫다. R5는 위험요인 ID(카탈로그 문구) 질의 전용 후보로만 본다.
- dev에서 추가로 시험한 변형(R1·R4·R5 순위 융합 RRF, 제목 단어만 재순위, 상위 조문 제목 의사 적합성 피드백)은 개선이 없어 채택하지 않았다(`results_261122`에 미포함).

## 6. 누출·한계

- 정답 조문은 AI가 조문 제목·원문을 읽고 정했다. 검색기 설정은 결과를 보기 전에 정했다. 결과를 보고 고친 규칙은 없다.
- 질의(카탈로그 문구)에는 법령 문장이 들어 있지 않다. 다만 카탈로그 키워드·조치 문구는 문서 B·C에서 왔고 문서 B 일부 쪽이 법령을 인용한다. 확장어와 조문 문구가 겹칠 가능성이 있다(R4·R5).
- `prior_gold_v0` 조문은 `risk_law_search` 규칙 보정(C 경로)에 쓰인 정답과 같다. 그 모듈 결과와 비교할 때 누출 가능성이 있다.
- CUT·MIX, ENV·LADDER처럼 위험요인끼리 정답 조문이 겹쳐 dev·holdout이 완전히 독립이 아니다.
- R1은 kiwipiepy 형태소 분석 대신 정규식 토큰을 썼다. 기존 보고서(kiwi·KURE C 경로 1순위 0.68)와 수치를 직접 비교할 수 없다.
- 임베딩(e5·KURE)·하이브리드·교차 인코더 재순위는 **미실행**이다. 로컬에 모델·torch가 없고 Cloud 실행은 하지 않았다.
- 출처 직접 인용 조문은 6개뿐이다. 나머지 core 24개는 전문가 검토가 필요하다.

## 7. 다음 작업 제안

1. 담당자가 `law_gold_spec.json`의 `ai_proposed` 조문과 `미확인` 11개를 검토한다.
2. Cloud 격리 폴더에서 KURE-v1 임베딩을 R5와 융합(하이브리드)하여 같은 스크립트로 비교한다. UV·ENV 같은 어휘 불일치 사례가 대상이다.
3. 서비스 연결은 팀 결정 후 진행한다. 예: 위험요인 ID별 검토 완료 조문만 `legal_registry`로 넘기고, 미검토 검색 후보는 '확인 필요'로 구분 표시.
