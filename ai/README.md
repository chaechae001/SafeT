# AI 작업 영역

| 경로 | 용도 |
|---|---|
| [experiments/](experiments/README.md) | 기존 추론·학습·비교 실험과 재현 조건. |
| [src/](src/README.md) | 향후 서비스 연결용 코드. 현재 안내만 있다. |

실험 코드의 경로와 파일 이름을 유지한다.
파이프라인 실험은 이웃 폴더의 모델 비교 코드를 불러온다.
실험 코드를 바로 서비스 API로 취급하지 않는다.

서비스 연결 전에 모델, 입력, 출력, 오류 처리와 실행 환경을 확정한다.
GPU 모델 환경과 OCR 환경을 구분한다.

## 실행 환경(Python)

- 본체(서비스·AI 추론·평가)는 Python 3.11로 실행한다(`.python-version`).
- 예외: SAM 3는 Python 3.12 이상이 필요해 별도 venv/컨테이너로 실행하고, 본체(3.11)와는 탐지 결과 JSON으로만 연결한다.
- 두 환경의 모델을 GPU에 동시에 올리지 않는다. SAM 3 프로세스가 끝나고 GPU 메모리가 반환된 뒤 본체 모델을 올린다.

## 입력별 담당 모델

AI는 추천만 한다. 최종 선택과 판단은 사람이 한다.

| 입력 | 모델 | 출력 |
|---|---|---|
| 사진 | SAM 3 (Python 3.12) | 기기 후보 JSON |
| 음성 | faster-whisper + large-v3-turbo | 텍스트 |
| 텍스트 | EXAONE 3.5 7.8B Instruct AWQ (Python 3.11) | 추천 JSON |

- SAM 3가 사진에서 기기 이름을 뽑으면, 다음 단계 입력은 글자뿐이다. 그래서 VL(비전+언어) 모델이 필요 없다.
- 같은 크기라면 텍스트 전용 모델이 한국어와 JSON 출력이 더 안정적인 편이다.

## GPU 메모리 운용

- 인스턴스 GPU는 약 9.7 GB다.
- 평소에는 LLM(약 6 GB)과 STT(약 2 GB)를 올려 둔다.
- 사진이 들어오면 LLM·STT를 내리고 SAM 3(약 7 GB)를 올린다. 탐지가 끝나면 SAM 3를 내리고 LLM·STT를 다시 올린다.
- 이렇게 순차 실행하면 7~8B 모델을 4비트로 줄여 같은 GPU에서 쓸 수 있다. 대신 시간이 더 걸린다.

| 구간 | 시간 |
|---|---|
| LLM·STT 내림 | 2.4초 |
| SAM 3 탐지(프로세스 시작과 모델 로딩 포함) | 49.3초 |
| **사진 도착 → 기기 확인 화면** | **52.5초** |
| 확인 화면 표시 뒤 LLM·STT 다시 올림 | 41.0초 |

확인 화면까지 걸리는 시간은 대부분 SAM 3 프로세스 시작과 모델 로딩이다.

## 기기 탐지 모델 비교

| 모델 | F1 | 재현율 | 정밀도 | 최대 GPU 메모리 |
|---|---|---|---|---|
| **SAM 3** | **0.53** | 0.62 | 0.46 | 6.89 GB |
| YOLOv8x-World | 0.30 | 0.38 | 0.24 | 0.78 GB |
| YOLO11x COCO | 0.25 | 0.28 | 0.24 | 0.81 GB |
| YOLOv8s-World | 0.22 | 0.28 | 0.18 | 0.27 GB |

내부 실험 점수이며 현장 성능이 아니다.

## 기기 탐지 임계값

- 서비스 기본값은 **0.35**다(`SAFET_DETECTOR_THRESHOLD`, 2026-11-18 DR 결정).
- 기준: 놓친 기기는 위험 평가에서 빠지고 사용자가 알아채기 어렵다. 그래서 재현율에 가중을 둔 F2가 가장 높은 값을 골랐다. 잘못 잡은 기기는 사진 확인 질문에서 사용자가 걸러 낸다.
- 평가: 평가셋 34장(AI 보조 라벨, 사람 검수 전), 이미지×기기 단위.

| T | 정밀도 | 재현율 | F1 | F2 | 사진당 오탐 | 사진당 놓침 | 사진당 박스(평균/최대) |
|---|---|---|---|---|---|---|---|
| 0.05(이전 기본) | 0.20 | 0.90 | 0.32 | 0.52 | 6.32 | 0.18 | 173 / 712 |
| 0.25 | 0.33 | 0.79 | 0.47 | 0.62 | 2.74 | 0.35 | 16 / 44 |
| **0.35** | 0.39 | 0.74 | 0.51 | **0.63** | 1.97 | 0.44 | 9 / 30 |
| 0.50 | 0.46 | 0.62 | **0.53** | 0.58 | 1.24 | 0.65 | 5 / 20 |

- EXAONE 입력 한도: 입력+출력(1,024)+여유(64) ≤ 4,096토큰이다. 지침과 카탈로그만으로 2,188토큰이라 사진 정보에 쓸 수 있는 몫은 약 820토큰이다.
  - 이전 방식(T 0.05, 박스 전체 전달)은 사진 1장도 18,329토큰으로 한도를 넘었다.
  - 그래서 사진마다 기기별 최고 점수 한 줄(예: `deep fryer 0.91`)만 넘긴다. 박스 좌표와 기기 ID는 넘기지 않는다. 기기 ID를 넘기면 모델이 `EQ_GRILL`을 카탈로그 ID `GRILL`로 착각한 사례가 있었다.
  - T 0.35에서 사진 4장까지는 기기가 가장 많은 사진으로도 한도 안이다(2,986토큰). 5장 이상은 사진에 따라 넘으며, 이때는 기존 `AI_INPUT_TOO_LONG` 안내가 나간다.
- 한계: 같은 34장에서 T를 골랐다. 치킨 매장 위주다. 사람 검수 라벨과 다른 업종 사진으로 다시 정해야 한다.

## 위험성 판정 기준

- 3단계 판별법을 쓴다.
  - 상(빨강): 사망·중상이 날 수 있다.
  - 중(노랑): 휴업이 필요한 부상이다.
  - 하(초록): 경미하다.
- 이전 검토안인 3×3 빈도·강도법(중대성 우선)은 이 방식으로 바꿨다.

[루트 환경 기록](../261113_observed_environment_DR.json)은 관측 버전이며 설치용 lock 파일이 아니다.

학습 데이터, 평가 정답, 모델 가중치와 실제 이미지는 이 저장소에 포함하지 않는다.
합성 데이터와 AI 보조 정답을 독립 현장 검증으로 표현하지 않는다.
