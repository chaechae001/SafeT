## 음식점 위험성평가 v2 — 서비스 연결 및 공통 참조 기준

반영일: <date start="2026-11-17" />

**구현 완료 범위:** 기존 Safe-T 평가표 작성 화면/API에 사진·텍스트·음성 전사 → 위험요인 추출 → 추가 질문 → 답변 재분석 → 상/중/하 판정·근거 → 저장·확정·읽기 전용 조회를 연결했습니다.

**남은 연결 사항:** Cloud 호출용 API 키는 발급된 상태이며, 실제 모델명·API 주소는 추후 확인 예정입니다. 이번 검증은 합성 모델 응답을 이용한 API·DB·브라우저 통합 검사입니다. 실모델 사진 추론, 음성 인식 정확도, GPU·OCR, 현장 판정 일치율을 검증한 것은 아닙니다. 운영 배포·원격 푸시·main 병합도 아직 하지 않았습니다.

### 상/중/하 운영표

아래 표는 공식 예시를 구현한 **보수적인 서비스 운영안**입니다. 정부가 정한 유일한 산식이나 통계적 사고 확률은 아닙니다. 정책 ID는 `RESTAURANT-3LEVEL-2.0`입니다.

| 사고 피해 | C1 필요한 조치 유효 확인 | C2 핵심 유효·일부 미흡 | C3 핵심 미이행·무효 |
|---|---|---|---|
| S1 경미·업무 지장 없음 | 하 | 중 | 중 |
| S2 치료·회복 필요 | 중 | 중 | 상 |
| S3 사망·영구장해 가능 | 상 | 상 | 상 |

- 기기 보유만으로 실제 사고 경로를 확정하지 않습니다. 작업 단계·노출 조건을 질문합니다.
- S3 경로가 남아 있으면 조치가 있어도 상입니다. 검증된 제거·격리로 경로가 없어지면 `closed`로 보존하고 남은 위험을 다시 평가합니다.
- 급박한 위험·검증된 현행 법정기준 미충족은 상, 같은 원인이 해소되지 않은 아차사고는 최소 중입니다.
- 미확인은 미설치와 구분합니다. 후보는 등급 null, 확인된 위험의 미확정 S/C는 가능한 범위와 잠정 최댓값을 표시합니다. 잠정 등급은 확정 신호로 저장하지 않습니다.
- 1/2/3은 정렬용 서열입니다. 평균점수·사고확률·사업장 안전 인증으로 바꾸지 않습니다.
- 장갑·교육의 개수로 핵심 방호 결함을 상쇄하지 않습니다. 회전체 작업과 전원 격리 후 날 취급의 보호구 조건을 구분합니다.
- 과거 수치·법령·제품별 응급처치는 시효와 적용 조건을 확인합니다. 구토 유도 같은 과거 문구를 AI 행동 지침으로 재생하지 않습니다.

### 서비스 동작과 판정 근거

1. 사진은 실제 `image_url` 콘텐츠로 모델에 전달합니다. 텍스트·음성 전사문·등록 기기는 미디어 ID로 구분합니다.
2. AI는 사고 경로, 피해 후보, 개별 조치 상태, 관찰/보고/추론 근거, 미확인·상충 정보, 추가 질문과 개선대책을 구조화합니다.
3. 서버가 JSON Schema·증거 ID·자료 쪽수·핵심 조치·신뢰된 법령 레지스트리를 검증하고 고정 코드로 등급을 계산합니다. 잘못된 응답은 하로 보정하지 않고 오류로 처리합니다.
4. 질문은 판정 영향·안전한 확인 방법과 함께 표시합니다. 답변을 넣으면 같은 평가표를 다시 분석하며 기존 항목 ID·선택·담당자·예정일을 보존합니다.
5. 현재 안전조치를 변경하면 이전 판정을 무효화하고 재판정을 요구합니다. 대책을 선택한 것만으로 위험도를 낮추지 않습니다.
6. 후보·잠정·미확인 질문·재판정 대기가 남으면 확정할 수 없습니다. 확정 후에도 사고 경로·조치 상태·근거·자료 출처를 조회할 수 있습니다.

사진에 보이지 않는 기능, 접지·누전차단기·인터록의 작동, 노출시간·화학 농도는 자동 확정하지 않습니다. 음성은 기존 브라우저 인식/전사문 수정 기능을 연결했으며, 서버 STT와 원본 음성 업로드는 이번 범위에 없습니다.

### API·데이터 계약

`POST /evals/{eval_no}/risk-answers`

```json
{
  "revision": 2,
  "answers": [
    {"question_id": "Q1", "answer": "현재 물기가 남아 있고 통행 통제가 없습니다."}
  ],
  "additional_text": "같은 통로로 뜨거운 국을 운반합니다."
}
```

응답은 기존 평가 상세에 `risk_assessment`, `risk_needs_reassessment`, 각 위험 항목의 `risk`를 추가합니다. `risk_assessment.analysis`에는 증거·사고 경로·조치·질문·대책, `results`에는 등급·판정 상태·범위·적용 규칙, `summary`에는 최고 등급과 미확인 수를 저장합니다. `work_authorization`은 `not_issued`입니다.

소유권·revision·질문 소속을 서버에서 검사합니다. 판정 필드·정책·법령 레지스트리는 클라이언트가 바꿀 수 없습니다. 기존 DB의 `eval_mst.risk_state LONGTEXT`에 정책 버전과 판정 근거를 저장하고 사진 원본은 기존 `eval_file`에서 복원합니다.

### Cloud 설정

서버의 `backend/.env`에서 설정합니다. 키는 이 페이지·브라우저 코드·커밋에 넣지 않습니다.

```dotenv
SAFET_ASSESSMENT_MODE=restaurant_v2
SAFET_AI_BASE_URL=https://YOUR-CLOUD-ENDPOINT/v1
SAFET_AI_MODEL=YOUR-CONFIRMED-MULTIMODAL-MODEL
SAFET_AI_API_KEY=YOUR-PRIVATE-KEY
SAFET_AI_MAX_TOKENS=12000
```

현재 어댑터는 `/chat/completions`, `messages`, `image_url`, `response_format: json_object` 호환 형식을 사용합니다. Cloud의 실제 API 계약·모델명·이미지 지원·컨텍스트 길이를 확인한 뒤 연결합니다. 다른 계약이면 어댑터를 바꾸고 판정 기준은 유지합니다.

```bash
python -m pip install -r backend/requirements.txt
# 개인 개발 DB 설정과 백업을 확인한 뒤
python backend/run_local.py --migrate
```

실제 Cloud 검증에 `--demo`를 사용하지 않습니다. 설정/응답 실패 시 합성 결과를 실제 판정으로 대신하지 않습니다.

### 검증 결과와 남은 작업

- 기존 기능 포함 API·DB·정책 테스트 98개 통과, skip 0개.
- 격리 MariaDB 11.8.3, 이번 테스트 Python 3.12. 기존 목표 Python 3.11 배포 환경 호환성은 별도 확인 필요.
- Edge 모바일에서 질문 답변 → 재판정 → 조치 변경 → 재판정 → 대책·담당자 → 확정 → 읽기 전용 근거 조회 확인. JavaScript 오류 없음.
- JSON·JavaScript 문법·문서 링크와 기존 CPU 자체 검사 3개 통과.
- Cloud 주소/모델 확인 후 실제 호출·JSON 응답 성공률·지연·사진 위험 누락률·전사 오류·전문가 판정 일치율을 확인해야 합니다.

### 이후 작업에서 참조하는 방법

이 페이지를 음식점 위험성평가 구현의 공통 참조점으로 사용합니다. 저장소 `AGENTS.md`와 README에도 연결했습니다. 정책 변경 시 정책 ID, 프롬프트, 스키마, 판정 코드, 테스트와 이 페이지 변경 이력을 함께 갱신합니다. 미확인을 하로 처리하거나 개선 계획을 완료로 간주하는 변경은 하지 않습니다. 구현 완료·통합 검증 완료·실모델 검증 완료·배포 완료를 구분해 기록합니다.
