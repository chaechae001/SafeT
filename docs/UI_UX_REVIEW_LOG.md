## 퍼널과 발표에 쓰는 기준

주 흐름은 ‘평가표 작성 시작 → 현장 입력 단계 완료 → 초안 생성 성공 → 작성 완료’로 정의한다. 로그인·첫 사업장 등록은 진입 경로이며 기존 사업장 사용자와 나눠 본다. 서명과 공유는 작성 완료 뒤의 선택 경로로 각각 기록한다. 임시 저장·재진입은 새 작성 건으로 중복 집계하지 않도록 분석 단위를 명시한다.

| 단계 후보 | 관찰 또는 향후 집계 기준 |
|---|---|
| 작성 시작 | 새 평가표 기본정보 화면 진입 |
| 현장 입력 단계 완료 | 해당 단계 검증을 통과해 다음 뷰에 진입 |
| 초안 생성 성공 | 생성 응답으로 평가표 번호를 받고 초안 화면이 로드됨 |
| 작성 완료 | 확정 요청 성공 후 완료 상태를 확인 |

전환율은 같은 기간·대상에서 ‘앞 단계에 진입한 고유 작성 시도 중 다음 단계에 도달한 수 ÷ 앞 단계 고유 시도 수’로 정의한다. 실제 집계 전에는 시도 식별 방식, 기간, 테스트 데이터 제외 조건을 정한다. 운영 이벤트가 확인될 때까지 ‘측정 전’으로 표기한다. 수동 검증의 클릭 수나 읽기 순서 변화는 화면 관찰 결과로 쓴다. 구현 로그를 실제 사용자 이탈률 개선으로 해석하지 않는다.

발표용 한 줄은 ‘어떤 사용자가 어떤 단계에서 겪은 문제인지 → 무엇을 바꾸었는지 → 화면이나 테스트에서 무엇을 확인했는지’ 순서로 쓴다. 수치가 있으면 측정 방법·대상 수·기간을 붙인다.

### UX-026 · 예상 위험도 카드 설명 접기

초안 상세와 확정 평가표에서 등급을 계산한 카드는 제목·ⓘ·현재 및 개선 후 예상 등급을 먼저 표시한다. 추가 조치 안내와 계산 설명은 ⓘ로 펼친다. 기존 카드의 색상·서체·요소 배치를 유지했다.

Edge 390×664에서 두 화면 모두 초기 접힘, 클릭 후 설명 표시, Enter로 다시 접힘과 aria-expanded 갱신을 확인했다.

### UX-027 · 작성 기본정보와 로그인 만료 후 평가일 복원

사업장 선택이나 평가일 변경만 한 상태에서도 새로고침 후 기본정보를 복원한다. 사용자가 건드리지 않은 빈 양식은 복원 안내를 띄우지 않는다. 로그인 만료 시 일반 자동 보관과 같은 스냅샷을 사용해 기본 평가일은 다시 연 날로, 사용자가 지정한 평가일은 입력한 날짜로 복원한다.

로컬 Edge의 검토 계정으로 빈 양식, 사업장만 선택, 날짜만 변경, 만료 후 기본 평가일, 만료 후 직접 입력한 평가일을 확인했다(5/5). 만료 처리는 앱의 만료 경로를 호출하고 실제 재로그인했다. 날짜 경계는 이전 날짜의 기본값으로 모사했다.

사업장 목록 조회가 지연되거나 실패한 상태에서 기기 선택 단계가 복원되면 사업장과 직접 추가한 기기가 빈 값으로 덮이는 문제도 수정했다. 목록이 정상 응답할 때까지 기존 선택을 유지한다. 독립 회귀 검사 `backend/unit_tests/browser_write_restore_smoke.py`로 조회 실패 → 재접속 → 사업장과 기기 복원을 확인했다.

### UX-028 · 사업장 관리에서 기기 등록 단계로 복귀

03 기기 등록에서 사업장 관리로 들어오면 목록에 ‘작성 중인 평가표로 돌아가기’를 표시한다. Edge 390×844에서 사업장 관리 새로고침 후 복귀, 사업장·참여자·작업 설명 복원, 일반 진입 시 버튼 숨김을 확인했다. 사용자는 앞서 안내한 나머지 항목의 휴대폰 확인을 완료했다.
