## 신규 평가표 정책 — FOOD-3LEVEL-1.2 (2026-11-21)

결정: 신규 실제 평가표는 FOOD-3LEVEL-1.2로 판정한다(#44 ce06af3 검토안을 서비스에 적용).
기존 CATALOG-MVP-1.1 평가표는 저장 당시 정책·결과·이력을 보존하고, 작성 중이면 저장된 정책으로 계속 편집·재계산한다.
1.1 → 1.2 재평가는 자동 전환하지 않는다. 1.2로 다시 평가하려면 새 평가표를 작성한다(명시적 전환 기능은 아직 없음).

| 확정 조건 | 일반 평가표: 현재 조치 1개 이상 또는 '현재 조치 없음', 등록 기기 확인 대기 모두 처리(목록 전체 확인 체크는 요구하지 않음, 2026-11-21). `catalog_v1`·`catalog_ai_v1`: 기존대로 목록 전체 확인 필요. 미매칭·시나리오 없음은 판단 필요·검토 흐름 |

이 기준과 충돌하는 아래 1.1 절의 문구는 기존 평가표·input_based v1에만 적용한다.
- '정보 부족 = 확인 필요(N)'·'저장할 때 계산'은 일반 평가표에서 '생성 시 0개 기준 계산'으로 바꿨다. 확정 차단은 유지한다.
- '사망·영구장해 경로가 남으면 하향하지 않는다'는 1.1 규칙이다. 1.2는 S3에서 핵심 조치를 모두 충족하면 중이 된다(최저 중).

다른 문서·Notion에서 이 기준을 인용할 때는 이 문서를 연결하고 정책 버전(FOOD-3LEVEL-1.2)을 함께 적는다.
입출력 계약: [INTERFACES.md — 일반 평가표 위험도 계약](../../contracts/assessment_authoring/v1/INTERFACES.md#일반-평가표-위험도-계약--food-3level-12-2026-11-21).

## 이번 구현 범위 (2026-11-17, 1.1 기준)

현재 위험도와 개선대책 선택·저장 후 예상 위험도를 구현한다.
예상 위험도는 선택한 기준 대책이 모두 이행되어 유효하게 작동한다는 가정의 결과다.
선택만으로 현재 등급을 낮추거나 실제 개선 완료로 표시하지 않는다.

| 항목 | 확정 내용 |
|---|---|
| 계산 담당 | AI는 위험 후보·조치 후보·근거 추출, 공통 서버 모듈은 등급 계산 |
| 현재 조치 | 사용자가 현재 실제 적용·작동 중임을 확인한 조치. 자동 체크하지 않음 |
| 미선택 | 목록 전체 확인 전에는 미확인, 확인 후에는 미실시로 해석 |
| 작업 적용 | 사용자가 해당 작업인지 확인. 등록 기기·키워드만으로 실제 노출 확정 금지 |
| 정보 부족 | 확인 필요(N). 임시저장 가능, 확정 차단 |
| 계산 시점 | 현재 조치 또는 개선대책을 변경하고 저장할 때 계산. 저장 전 재계산 필요 표시 |
| 예상 위험도 | 현재 조치에 선택한 기준 대책의 이행·효과를 가정해 상·중·하 계산 |
| 직접 추가 | 저장하되 기준 ID와 연결되지 않은 대책으로 자동 하향하지 않음 |
| 이력 | 사용한 정책 버전·현재 결과·예상 결과를 기록. 과거 기준 덮어쓰기 금지 |

|---|---|---|---|

2026-11-21까지의 서비스 운영 기준이다. 신규 평가표는 위 FOOD-3LEVEL-1.2를 쓴다. 현재 작업에서 현실적으로 가능한 피해를 전제로 한다.
중대 사고 경로가 남으면 조치 선택만으로 하향하지 않는다. 경로 제거는 별도 재평가 대상이다.
조치 유효성은 사용자 확인을 전제로 하며 프로그램이 현장 사실을 자동 보증하지 않는다.

## 팀 연결 예시 (1.1 기준)

1.2 예: FRY(S2) 핵심 3개를 개선대책으로 선택 → 현재 중 / 예상 중, 보완(FRY-C7)까지 → 예상 하. FIRE(S3) 핵심 전부 → 현재 상 / 예상 중(보완까지 선택해도 중).

치료·회복 수준의 피해가 가능한 작업, 현재 핵심 조치 없음 → 현재 상.
필요한 기준 개선대책을 모두 선택하고 저장 → 현재 상 유지 / 예상 중.
이는 대책 이행·효과를 가정한 예상이며 실제 개선 완료를 뜻하지 않는다.
사망·영구장해 사고 경로가 남는 작업은 모두 선택해도 현재·예상 상을 유지한다.

## 역할과 인계

AI·계산 담당: 기준 데이터·공통 계산·AI/RAG 후보와 근거. 화면·문서 담당: 화면·선택·저장·확정·조회.
이번 변경으로 저장 항목에 controls_reviewed(작업 해당 및 현재 조치 목록 전체 확인)를 추가한다.
DB 추가 열 없이 기존 catalog_state에 확인 상태를 저장한다. 기본값은 false다.
화면은 현재 조치 목록 끝에 확인 체크를 제공하고, 선택 변경 시 확인을 해제한다.
이전 정책 문서는 조회 가능하나 수정 시 새 평가표를 작성한다. 정책 데이터는 새 버전으로 적재한다.
AI/RAG 실모델 연결·현장 정확도 검증은 별도 후속 작업이며 이번 규칙 검증으로 대체하지 않는다.
