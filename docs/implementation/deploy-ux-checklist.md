# 화면 개선(UX-001~017) 배포 반영·휴대폰 확인 점검표 · 2026-11-22

이 문서는 배포 담당이 `ux/screen-review-261122` 변경을 배포 서버(`/proxy/8022/`)에 반영할 때 씁니다. 반영 뒤 휴대폰 확인에도 씁니다.
배포 서버 설정은 저장소 밖에 있습니다. 아래 "현재 상태"는 2026-11-22에 배포 주소를 읽기만 해서 확인한 결과입니다.

## 현재 배포 상태(읽기 확인)

| 확인 | 결과 |
|---|---|
| `/proxy/8022/pages/login.html` | 200. UX-001 이전 화면 |
| `/proxy/8022/` | 307로 `/proxy/8022/proxy/8022/pages/login.html`로 이동. 하위 경로가 두 번 붙어 깨짐 |
| `/proxy/8022/pages/error.html` | 404(파일 없음) |
| `js/api.js` 첫 줄 | `window.SAFET_API_BASE = "/proxy/8022/api";`를 배포 때 직접 넣고 있음 |

## 1. 서버(API)

- **DB 구조**: 변경이 없습니다. 새 마이그레이션 파일도 없습니다.
  - UX-016의 서명할 사람 추가는 기존 `eval_member`에 행을 넣습니다.
  - UX-017의 `item_count`는 조회만 합니다.
- **`.env`**:
  - `SAFET_GUEST_KEY`: 게스트 QR을 쓸 때만 24자 이상으로 넣습니다. 비워 두면 게스트 로그인은 꺼집니다.
  - `SAFET_GUEST_EMAIL`: 선택입니다.
  - `SAFET_DEV_MAIL_OUTBOX`: 운영에서는 **비워 둡니다**.
  - `SMTP_*`: 실제 메일 발송용입니다.
- **재시작 후 확인**: `/proxy/8022/api/docs`에서 다음 두 가지가 보여야 합니다.
  - `POST /evals` 요청 칸에 `add_custom_machines`
  - `GET /evals` 응답에 `item_count`

## 2. 화면(정적 파일)

- `frontend/` 전체를 바꿉니다. 새 파일도 함께 올립니다: `pages/error.html`, `js/ui-icons.js`, `js/draft-edit.js`, `js/ux-guide.js`, `css/ux-guide.css`, `public/guide/*`.
- `js/api.js` 맨 위에 `window.SAFET_API_BASE = "/proxy/8022/api";`를 **다시 넣습니다**. 새 `api.js`로 덮어쓰면 이 줄이 사라집니다.
- 권장: `api.js`를 고치는 대신 각 HTML의 `api.js` 앞에서 설정을 읽게 바꿀 수 있습니다(예: `<script src="../js/config.js">`). 이 방법은 저장소 변경이 필요해 별도로 결정합니다.

## 3. nginx

- **루트 이동**: `/proxy/8022/` 요청은 **상대 주소** `pages/login.html`로 보냅니다(`Location: pages/login.html`). 지금처럼 절대 경로로 보내면 하위 경로가 두 번 붙습니다.
- **오류 페이지**: 404·5xx는 `pages/error.html`을 같은 상태 코드로 보여 줍니다. 이 파일은 `<base>` 기준 상대 경로를 써서 하위 경로에서도 깨지지 않습니다. 로컬 기준은 `backend/dev_static_server.py`입니다.

## 4. 반영 직후 PC 확인

1. 로그인 화면이 새 디자인(시작 화면 → 로그인)으로 나오는지 확인합니다.
2. 루트 주소, 없는 주소(오류 화면), 로그인 API 호출을 확인합니다.
3. 가입 `보기 >` 창에 4가지 고지가 나오는지 확인합니다.
4. 03 기기에서 직접 추가한 뒤 초안을 생성하고, 초안에 기기가 저장됐는지 확인합니다.
5. 내 평가표 카드에 `위험 항목 N건`이 나오는지 확인합니다.
6. 06 확정 화면 `서명하기` → 07 서명 화면으로 가는지 확인합니다.

## 5. 휴대폰 확인(배포 주소, https)

https 주소라 휴대폰에서도 카메라와 마이크를 쓸 수 있습니다. QR이나 주소로 접속하고, 합성 계정만 사용합니다.

| 영역 | 확인 |
|---|---|
| 터치 | 버튼·칩이 한 번에 눌리는지, 05 카드 밀어서 삭제, 달력·선택 상자 |
| 키보드 | 입력칸·하단 버튼·`기기 직접 추가` 창 입력칸이 키보드에 가리지 않는지 |
| 사진 | `사진 찍기`(카메라)와 `사진 불러오기`(앨범), 6장 초과 안내 |
| 녹음 | 마이크 권한 요청 → 시작·일시정지·중지·재생, 한국어 전사 |
| 글자 확대 | 시스템 글자 크기 최대에서 줄바꿈·잘림·가로 스크롤 |
| 화면 낭독기 | 안드로이드 TalkBack, 아이폰 VoiceOver로 아래 세 가지를 확인 |

화면 낭독기 확인 항목:
- 아이콘 버튼 이름이 읽히는지
- 오류 문구가 읽히는지
- 창이 열린 뒤 초점이 창 안으로 이동하는지

결과는 기기·OS·브라우저 버전과 함께 `docs/UI_UX_REVIEW_LOG.md`에 기록합니다. 실제로 확인하지 못한 항목은 미확인으로 남깁니다.
