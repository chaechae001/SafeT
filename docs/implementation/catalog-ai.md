# 입력 해석과 DB 위험성평가 연결

사진·텍스트·브라우저 전사문에서 관찰과 사용자 보고를 추출해 DB 시나리오·조치 ID에 연결한다. 기기 등록을 작업 수행 증거로 쓰지 않는다.
모델이 만든 등급·조치 문구·출처는 받지 않는다. 조치와 문헌 출처는 DB 스냅샷을 사용하고, 현재·예상 위험도는 `domain/risk_policy.py`의 CATALOG-MVP-1.0으로 계산한다.

## 저장 계약

- `catalog_state`: DB 스냅샷·조치 ID 연결·공통 계산 결과와 AI 연결 근거·미확인 조치.
- `risk_state`: 근거 계약 버전·입력의 미디어 ID·추출 보고. 사진 원본은 기존 `eval_file`에 저장하며 보고에는 중복 저장하지 않는다.
- `risk_event`: revision별 현재·예상 계산 결과. 실패한 재확인은 트랜잭션을 되돌린다.
- 현재 조치 변경은 저장 시 공통 함수로 다시 계산한다. 계획만 선택해도 현재 위험도는 바뀌지 않는다.
- 재확인의 새 미확인·상충 정보는 과거 체크값이나 과거 조치 없음으로 자동 해소하지 않는다. 현재 조치를 실제로 변경하거나 질문에 답해 해당 정보를 확인한다. 계획 선택·변경 없는 저장으로 확정 가능한 상태가 되지 않는다.
- 재확인 시 기존 항목·현재 선택·담당자·예정일을 보존하고 근거를 갱신한다. 새로 연결된 DB 항목만 추가한다.
- 근거는 current/planned/unknown 시점을 구분한다. 현재 존재·부재와 확정 적용에는 현재 근거가 필요하며 질문 문구는 사용자 보고로 인용할 수 없다.
- 인증·소유권·revision·확정 잠금은 기존 평가표 경로와 같다. 읽기 전용 조회에 근거·출처를 함께 반환한다.

## 화면

기존 작성 → 초안 → 위험 상세 → 확정 → 읽기 전용 흐름을 사용한다. 초안의 입력 안내 영역에 필요한 질문을 표시하고 상세의 판단 이유 옆에 근거를 표시한다. 질문 답변은 선택적으로 제출할 수 있고 확정 시 미확인 정보를 검사한다. 별도 작성 화면이나 등급 직접 입력은 추가하지 않는다.

## 실행과 검사

서버 환경변수와 명령은 [backend README](../../backend/README.md#ai-입력-해석과-db-연결)를 참조한다.
실제 Cloud 주소·멀티모달 모델·API 호환성은 팀 확인이 필요하다. 실제 사진 해석·전사 정확도·GPU·OCR·현장 누락·판정 일치·시간·비용은 합성 검사로 검증되지 않는다.
원본 음성의 서버 STT와 법령 전체 자동 판별은 포함하지 않는다. 최종 안전 판단은 담당자가 한다.

## 동시 요청과 이전 기록

MariaDB 스냅샷 잠금 충돌(1020)은 최초 쓰기 잠금에서만 롤백 후 한 번 다시 읽는다. 쓰기·모델 호출 전에 재조회하며 최신 소유권·revision·확정 상태를 검사한다. 이미 모델을 호출하거나 편집한 트랜잭션 전체를 자동 재실행하지 않는다.
[MariaDB 스냅샷 격리 설명](https://mariadb.com/docs/server/server-usage/storage-engines/innodb/innodb-system-variables#innodb_snapshot_isolation).
근거 계약 `CATALOG-AI-1.1` 이전의 작성 중 기록은 시점 재확인 전까지 현재·예상 신호를 판단 필요로 표시하고 확정을 막는다. 확정된 기록은 이전 분석임을 표시하며 저장 당시 결과를 보존한다.
답변은 질문 문맥과 실제 답변을 분리해 한 미디어로 저장한다. 여러 위험의 질문이 100개를 넘어도 답변 수 때문에 정상 재확인이 막히지 않으며, 해결된 질문의 임시 답변은 화면에서 정리한다.
