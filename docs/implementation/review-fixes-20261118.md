# 검토 의견 반영

실제 모델 호출 없이 모의 AI와 격리 테스트 DB로 검증한다. 개인 이름은 기록하지 않는다. 사용자 검토 승인 후 PR #25에 반영한다.

| 지적 사항 | 반영 내용 |
|---|---|
| 동시 저장 500 오류 | 최초 잠금의 MariaDB 1020은 읽기 트랜잭션을 종료하고 한 번 재시도. 계속 충돌하거나 1205·1213이면 409로 안내. AI 호출이나 쓰기 전체를 자동 반복하지 않음 |
| 사진 질문 누락 | AI 질문을 9개로 자르던 코드 제거. 사진 확인 질문을 포함해 후보당 11개까지 보존. 전체 100개 초과 등 한도 위반은 오류로 안내하며 질문을 버리지 않음 |
| 외부 AI 동안 DB 잠금 | 초안 생성·위험 추가·답변 반영은 먼저 읽은 자료로 잠금 없이 분석. 저장 직전에 다시 잠금·소유권·삭제·확정 상태·revision을 확인. 생성은 사업장 정보도 대조 |
| 사진 반복 탐지 | 최초 탐지 결과와 사진·임계값 지문을 기존 catalog_state의 ai_analysis에 저장. 동일 사진의 질문 답변·항목 추가는 저장된 탐지를 재사용. 사진·임계값 변경이나 서버 내부 명시 재탐지는 새로 호출 |
| 휴지통 경합 | 휴지통 최초 잠금에도 같은 충돌 처리를 적용. 인증 조회 후 다른 요청이 복원한 자료를 만료 삭제하지 않는 검사 추가 |
| 기존 기준·남은 코드 | 정책 1.1은 그대로 유지. 이전 자료·risk_state·기존 마이그레이션은 보존. 어느 화면에서도 참조하지 않는 risk-assessment.js 제거 |

## 저장 방식과 화면 영향

새 DB 테이블이나 열은 없다. 서버가 저장한 탐지 스냅샷만 재사용하며 외부 요청으로 캐시를 주입할 수 없다. 기존 평가표에 캐시가 없으면 다음 사진 분석 때 한 번 생성한다. 삭제·복원 시 해당 평가표의 기존 JSON 상태와 함께 보존된다.

화면 저장·답변 요청 형식은 추가로 바뀌지 않는다. 동시 수정은 409 안내를 받고 기존 입력을 확인한 뒤 다시 요청한다. AI 분석 중 다른 탭에서 수정·삭제·확정했다면 이전 분석 결과로 덮어쓰지 않는다. 동일 요청 키로 생성이 겹치면 하나의 문서를 반환한다.

질문 한도 계약은 10에서 11로 변경됐다. 전체 100개 한도는 유지하며 질문이 남은 항목은 N(판단 필요), 확정 불가이다. 이전 질문이 재분석에서 누락되는 것도 계속 차단한다.

정책 1.0 평가표는 조회만 유지하고 수정·확정에는 새 평가표를 안내한다. 공용 DB 자료나 기존 마이그레이션을 임의 삭제하지 않는다. S3 등급 기준은 기존 확정 문서대로 유지한다.

## 검사 항목

- 인증 조회 → 다른 저장 커밋 → 기존 세션 저장: 500 대신 409.
- 분석 중 독립 DB 연결이 1초 제한 안에 수정·삭제·확정 가능. 분석 결과 저장은 해당 변화 감지 후 거절.
- 사업장 수정·삭제가 생성 중 발생하면 새 초안 저장 차단. 중복 요청은 한 문서로 정리.
- 질문 10개 + 사진 확인 1개를 보존. 답변·재조회 후에도 미응답 질문과 사진 캐시 유지.
- 동일 사진 답변 시 탐지 1회 유지, 사진 변경 시 재탐지.
- 인증 조회 스냅샷과 휴지통 복원·만료 삭제 경합 검사.

## 남은 작업

토큰 계수 API 지원 및 사용량 관련 답변 후 실제 모델 검증을 재개한다. 현재는 실제 호출 중단 상태를 유지한다. 실제 기기 인식 정확도와 최종 텍스트·사진 전체 흐름은 이 모의 검사로 대체하지 않는다.
