# 사진 없는 실제 EXAONE 초안 검토 · 2026-11-18

## 범위

사용자가 승인한 사진 없는 실제 모델 검사다. 팀 EXAONE에 서비스 프롬프트·카탈로그 후보 목록과 합성 현장 설명을 전달했다. 사진, 실제 사업장 자료, 개인 식별 정보는 보내지 않았다. SAM·SMTP는 사용하지 않았다. API 키는 출력·문서화하지 않았다. DB 설정은 기존 격리 테스트 DB를 명시적으로 주입했고 사용자 .env의 DB 값은 변경하지 않았다.

## 실제 확인 결과

1. 단독 분석: 매일 감자튀김을 조리하고 뜨거운 기름을 다룬다는 합성 설명에서 FRY 후보 생성 및 서버 스키마 검증 성공. model은 exaone-3.5-7.8b-instruct-awq.
2. 실제 API·격리 DB 검사: 명확한 작업 설명, 실제 사용 여부가 불명확한 보유기기 설명 두 사례에서 초안 생성·저장까지 진행됐다. 최초 신호는 판단 필요이며 추천 조치는 자동 체크되지 않음을 확인했다.
3. 명확한 작업 사례의 추가 질문 답변은 저장됐으나 안전장치·교육 확인 질문이 반복돼 검사 실패. 작업 해당 여부 질문과 다음 화면의 현재 조치 선택이 중복되는 문제다.
4. 불명확한 사례는 재분석 단계에서 AI_REQUEST_FAILED로 실패했다. 정확한 상위 서버 실패 원인은 확인하지 못했다.
5. 프롬프트 보완 후 재실행은 생성 전 AI_TOKENIZE_FAILED로 중단됐다. 후속 상태 확인에서 EXAONE /health와 /v1/models 모두 HTTP 500을 확인했다. 로컬 설정만의 문제로 단정하지 않는다.

실제 모델을 사용한 현재·예상 위험도 저장 → 확정 → 재조회 전체 통과는 아직 확인하지 못했다. 기존 모의 AI 통합 검증과 구분한다.

## 이번 변경

- ai/catalog_ai/system_prompt.md: 작업·노출이 명확하면 질문을 끝내고, 안전조치 유무·교육 등은 다음 조치 선택 화면에 맡기도록 명시했다. 최신 답변이 해소한 질문을 반복하지 않도록 지침을 보강하고 근거를 간결하게 요청했다.
- backend/services/catalog_ai.py: 분석 기록의 prompt_version을 catalog-ai-2로 올렸다. 계산 기준·등급 결정·토큰 제한은 변경하지 않았다.
- backend/tests/live_text_ai_smoke.py: 사진 없는 실제 모델 통합 검사 두 사례를 추가했다. 일반 테스트에서는 자동 실행하지 않고 명시 실행하며, 격리 DB와 API 키가 필요하다. 테스트 계정 자료는 기존 fixture로 정리한다.
- backend/README.md: 명시 실행 방법과 외부 모델 호출 범위를 추가했다.

프롬프트 개선 효과는 서버 복구 후 실제 모델로 재검증해야 한다. 질문을 코드에서 임의로 지우거나 실패를 성공으로 대체하지 않았다.

## 서버 복구 후 할 일

1. AI 서버 담당자에게 EXAONE 8000 포트도 /health 및 /v1/models가 HTTP 500이라고 전달하고 실행 상태·현재 공개 주소를 확인한다.
2. 동일한 실제 모델 두 사례를 다시 실행한다. 질문 답변 후 충분한 정보가 있으면 질문 종료, 부족하면 미판정 유지 여부를 확인한다.
3. 현재 조치 없음은 현재 상, 전체 기준 개선대책 선택·저장 후 예상 중, 현재 상 유지, 확정·재조회까지 검증한다. 이 등급 예시는 FRY 합성 사례에만 해당한다.
4. SAM 복구 후 사진 흐름을 별도로 검증한다.

커밋·푸시는 하지 않았다. 사용자 검토 후 진행한다.

- 저장소 지정 CPU 자체 검사 3종 통과.
- Python 구문, 계약 JSON 구문, git diff --check 통과.
- 이번 실제 모델 검사에서는 전체 완료 0건: 최초 2건 실패(반복 질문, 재분석 요청 실패), 보완 후 1건은 토큰 계수 서버 실패로 중단. 개별 초안 생성 성공을 전체 통과로 보고하지 않는다.
