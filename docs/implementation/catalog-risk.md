# DB 기준 위험도 계산

- 현장 설명·전사문·등록 기기의 키워드로 DB 위험요인과 조치 후보를 찾는다.
- 기존 화면의 현재 조치 선택 또는 조치 없음을 저장하면 현재 위험도를 계산한다.
- 개선대책을 선택하면 같은 계산 함수로 개선 후 예상 위험도를 계산한다.
- 예상 결과는 계획 이행을 가정한 값이며 현재 위험도를 변경하지 않는다.
- 조치를 입력하지 않으면 판단 필요(N)로 유지한다. 직접 추가한 조치는 저장하지만 기준 ID가 없으면 감점하지 않는다.
- 등급은 서버가 계산하며 클라이언트에서 직접 지정할 수 없다.

## 계산 기준

| 피해 | 필요한 조치 모두 선택 | 핵심 조치 선택·보완 미흡 | 핵심 조치 미선택 |
|---|---|---|---|
| 경미 | 하 | 중 | 중 |
| 치료 필요 | 중 | 중 | 상 |
| 사망·영구장해 가능 | 중 | 상 | 상 |

MVP 운영 규칙이며 선택 내용의 현장 유효성을 자동 검증하지 않는다.

## 구성

- `backend/domain/risk_policy.py`: 현재·예상 위험도 공통 함수
- `backend/services/catalog_risk.py`: 후보 조회·평가표 저장·재계산
- `contracts/catalog_risk/catalog.json`: 시나리오·조치 ID·출처·버전
- `risk_catalog`: 버전별 기준 데이터
- `eval_dtl.catalog_state`: 평가 당시 기준과 현재·예상 결과
- `risk_event`: 계산 결과 이력

기준 데이터는 같은 버전으로 덮어쓰지 않는다. 이전 정책 평가표는 조회할 수 있으며 수정하려면 새 평가표를 작성한다. 기본 작성·저장·확정·조회 API와 화면은 유지한다.
