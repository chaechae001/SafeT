# 8010 관문 연결 검토

## 변경

- `SAFET_AI_GATEWAY_URL` 하나로 EXAONE·SAM 요청을 보낸다. 설정 시 기존 개별 모델 주소보다 우선하며 우회 호출하지 않는다.
- 텍스트와 사진 모두 `SAFET_AI_API_KEY`로 인증한다. 관문 사용 시 키가 없으면 호출 전에 차단한다.
- 각 모델 요청의 읽기 대기를 180초로 통일했다. 사진 탐지 → 토큰 계수 → 초안 생성의 순차 호출을 고려해 브라우저 AI 요청 대기를 150초에서 600초로 늘렸다. 일반 API는 기존 15초를 유지한다. 자동 재시도는 추가하지 않았다.
- `.env.example`과 로컬 `.env`에 관문 주소를 반영했다. 기존 API 키는 그대로이며 Git에 포함하지 않는다.
- 공통 위험도 계산과 4,096토큰 제한은 유지한다.

## 실제 경로 확인

기본 주소: https://gdqtaahjfkzgzzxr.tunnel.elice.io/proxy/8010

| 경로 | 확인 결과 |
|---|---|
| GET /health | 200. 관문 상태와 STT 실행 상태 반환 |
| GET /v1/models | 200. EXAONE model ID와 max_model_len=4096 확인 |
| POST /v1/chat/completions | 관문 지원 목록에 있음. 키 없는 요청 401 확인 |
| POST /v1/detect | 키 없는 요청 401. 인증된 합성 JPEG 탐지 성공 |
| POST /tokenize | 404, 현재 미지원 |
| POST /v1/tokenize | 404, 현재 미지원 |
| GET /openapi.json | 404 |

404 응답의 지원 목록에는 /v1/info, /v1/completions, /v1/transcribe, /v1/mode도 있었다. 음성 입력이나 수동 모드 전환은 이번에 시험하지 않았다.

## 실제 시험 결과와 제한

- 사진 없는 합성 텍스트 초안: AI_TOKENIZE_FAILED. 토큰 계수 실패로 생성 요청 전에 중단했다.
- 합성 흰색 JPEG 256×256 한 장: SAM 응답 스키마 검증 성공, 모델 sam3, 탐지 0건, 약 41.7초. 모델 전환을 포함한 호출이며 별도 전환 소요 시간은 측정하지 않았다.
- 합성 사진 시험은 연결·인증·응답 형식을 확인하는 검사이며 실제 음식점 기기 인식 정확도를 보증하지 않는다.
- 토큰 계수 미지원 때문에 텍스트 초안과 사진 → EXAONE 전체 흐름은 통과하지 못했다. 계수 API가 준비될 때까지 임의 토큰 추정이나 기존 8000 주소로 우회하지 않는다.

## 서버에 필요한 보완

관문에 POST /tokenize를 추가해 EXAONE 모드 전환을 기다린 뒤 vLLM의 토큰 계수 API로 전달해야 한다. 텍스트 생성과 같은 인증·model·messages·채팅 템플릿을 사용하고 정수 count를 반환해야 한다. 계수와 생성 사이 모드가 바뀌어도 각 요청은 정상 대기 처리해야 한다.

요청 예시(키는 환경변수로만 전달):

```json
{"model":"exaone-3.5-7.8b-instruct-awq","messages":[{"role":"user","content":"합성 시험"}],"add_generation_prompt":true}
```

응답의 count는 실제 템플릿 적용 입력 토큰 수여야 한다. 클라이언트는 count + 출력 예산 + 여유 64가 4096 이하인지 확인한다.

## 로컬 회귀 검사

전체 자동 테스트 158개 통과(외부 라이브러리 경고 1건), 모의 AI 브라우저 오류 후 재시도·삭제·복원·확정·영구 삭제 통과, CPU 자체 검사 3종 통과. 코드·계약 구문 검사 통과. 실제 텍스트 초안 실패와 합성 사진 연결 성공은 위 실제 시험 결과와 구분한다.


## 서버 대기 중 보강

인증 오류(401), 호출 제한(429), 서버 오류(500), 시간 초과, 잘못된 토큰 수 4종에 대해 추가 생성·자동 재시도가 없는지 모의 테스트 8개를 추가했다. 관련 테스트 36개 통과. 이 보강에서는 실제 관문·모델을 호출하지 않았다. 직전 전체 회귀 158개 통과 기록과 구분한다.

## 토큰 제한과 사용량

- 4096은 배포 모델의 한 요청당 입력+출력 길이 한도이며 계정의 잔여 토큰이 아니다.
- 현재 출력 예산 1024, 여유 64를 제외한 입력 허용량은 3008이다. 입력에는 사용자 설명뿐 아니라 지침·후보 목록·기기 정보·답변 이력과 채팅 템플릿도 포함된다.
- count는 위 입력의 실제 길이다. 사전 계수는 초과 요청과 불완전한 JSON 응답을 줄이기 위한 현재 구현의 선택이다. 별도 계수 API 자체가 모든 AI 서비스의 필수 조건은 아니다. 동일한 토크나이저·템플릿의 로컬 계수나 서버의 검증·예산 조절 방식으로도 설계할 수 있지만, 현재 구현은 검증 실패 시 생성을 차단한다.
- 토큰 계수는 답변을 생성하는 추론과 다르며 모델 가중치·학습 데이터를 소모하지 않는다. 요청 처리에는 CPU·GPU·메모리·네트워크 등 자원이 쓰이고 로그 저장량은 증가할 수 있다.
- 엘리스 공식 런박스 안내는 서버 리소스의 시간 기반 이용을 설명한다. 프로젝트 지원 크레딧·사용 기한·시간 한도·별도 호출 제한·초과 과금 조건은 해당 계정에서 확인해야 한다. API 주소와 model ID만으로 잔여량이나 비용을 알 수 없다.
- 서버가 계속 실행 중이면 테스트를 멈춰도 할당 시간 비용이 계속 발생할 수 있다. 토큰 수와 서버 요금을 동일하게 계산하지 않는다. 공유 인스턴스를 임의 종료하지 않는다.

### 이번 관문 검증에서 확인한 범위

직전 관문 연결 검사에서 실제 EXAONE 답변 생성은 0건(계수 미지원으로 차단), SAM 합성 이미지 처리 1건(약 41.7초)이었다. 41.7초는 전환·통신 대기를 포함한 호출 경과 시간이며 청구 GPU 시간 측정값은 아니다. 그 이전 EXAONE 시험들의 총 토큰 사용량은 집계하지 않아 전체 누적 비용을 제시할 수 없다.

향후 정상 생성 1회는 현재 설정상 입력+출력 최대 4032토큰 범위이다. 이는 처리량 상한이며 실제 사용량이나 토큰 과금액이 아니다. 실제 값은 응답 usage 또는 서버 계측으로 확인해야 한다. 사진은 SAM 처리와 EXAONE 설명 생성이 별도이며 사진 수만으로 토큰 비용을 계산하지 않는다.

확인할 정보: 팀 잔여 크레딧/시간, 시간당 차감 단가, 지원 종료일, 켜둔 시간의 차감 여부, 저장공간 등 별도 요금, 요청·토큰 별도 제한. 실제 단가가 H/시간이고 추가 실행 시간이 t시간이면 시간 요금은 H×t이며, 프로젝트 약정과 별도 항목에 따라 달라진다.
