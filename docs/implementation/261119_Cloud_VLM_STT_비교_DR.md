# 음식점 사진·음성 모델의 Cloud 비교

2026-11-19 KST에 A100 MIG 1g.10gb(9,728 MiB)에서 실행했다. 사진 34장에서는 Qwen3-VL이 기기 누락과 오탐을 모두 줄였다. 사진의 기기명 후보 추출에 Qwen을 사용하는 후속 검증을 제안한다. 위험요인 설명까지 Qwen으로 일괄 전환하는 변경은 보류한다. 실제로 원문과 반대되는 설명이 나왔다.

## 같은 입력의 측정 결과

| 항목 | 현재 · SAM 3 + EXAONE + Whisper | 제안 · Qwen3-VL + Whisper |
|---|---:|---:|
| 사진 34장 · 정탐 / 오탐 / 누락 | 43 / 67 / 15 | 49 / 39 / 9 |
| 기기 정밀도 / 재현율 / F1 | 0.391 / 0.741 / 0.512 | 0.557 / 0.845 / 0.671 |
| 튀김기가 명확한 사진 17장 · 식별 성공 | 11/17 | 17/17 |
| 사진 1장 처리 · 중앙값 / 95백분위 | 4.37 / 4.68초 | 2.41 / 10.72초 |
| 추천 25건 · 유효 출력 | 24/25 | 23/25 |
| 추천 1건 처리 · 중앙값 / 95백분위 | 5.08 / 22.43초 | 22.21 / 39.03초 |
| 기기 질의 7건 · 상위 3개 재현율 | 0.619 | 0.619 |
| 기존 분류상 누출 위험이 낮은 4건 · 상위 3개 재현율 | 0.750 | 0.750 |
| 혼합 입력 1건 · 음성 → 사진 → 추천 | 131.09초 | 34.49초 |
| 합성 한국어 음성 1건 · 전사문 일치 | 1/1 | 1/1 |

사진은 같은 JPEG 파일 34장을 한 장씩 처리했다. SHA-256이 기존 업로드 목록과 모두 일치했다. AI 보조 라벨에서 명확한 기기 58개를 양성으로 썼다. 일부만 보이는 기기와 판독 불가 후보는 오탐 계산에서 제외했다. 기기별 박스나 마스크는 평가하지 않았다. 사진별 처리 시간이 짧은 순서에서 95% 지점의 관측값을 95백분위로 썼다.

추천은 RAG v2.1의 같은 기기별 후보와 출처를 두 모델에 입력했다. 첫 응답의 JSON, 후보 코드, 해당 후보에 속하는 출처 ID, 비어 있지 않은 설명, 중복 코드를 검사했다. 유효하지 않은 응답은 빈 추천으로 채점했다. 상위 3개 재현율은 기존 v2 평가 자료에서 질의별 정답 코드 중 상위 3개에 든 비율을 평균한 값이다. 위험 코드 정답과 기기 대응은 전문가 검수 전이다. 검수표의 누출 표시는 이전 인덱스 기준이다. v2.1 전체에서 독립성은 확인하지 않았다.

혼합 입력은 같은 튀김기 사진, 합성 음성, 확인된 기기와 전사문, 미리 검색한 후보로 한 번씩 재생했다. 사람 대기, 실시간 검색, 프런트엔드와 위험도 계산은 제외했다. 현재 방식은 기존 게이트웨이와 모델 자동 전환을 사용했다. 새 방식은 적재된 모델을 같은 프로세스에서 재사용했다. 두 방식 모두 이 사례에서 화상 코드를 첫 번째로 제시했다. 두 값은 이 조건의 사용자 흐름을 비교하는 참고값이다. 신규 방식의 운영 API 지연은 측정하지 않았다.

## 근거 대조와 결정

- 튀김기 질의에서 Qwen이 연결한 `CHK-4-2-3-07`은 국솥의 차열판이 설치돼 있다는 점검 문장이다. Qwen은 이를 튀김기 차열판이 설치되지 않았다는 근거로 설명했다. 기기와 설치 여부가 모두 달랐다. ID 검사만으로 걸러지지 않는 오류다.
- EXAONE은 식기세척기 응답에서 위험 코드를 중복했다. Qwen은 배기후드와 소형 화물용 승강기 응답에서 위험 코드와 출처의 연결을 위반했다. 이 집계는 최초 응답 기준이다.
- 같은 질의의 EXAONE도 일반 환기 점검 문구를 근거로 위험이 관리되고 있다고 설명했다. 두 모델 모두 점검표 문장만으로 개별 매장 상태를 확정할 수 없다. 설명 전체의 사실 정확도는 아직 독립 검토 전이다.
- Qwen의 사진 출력은 기기 ID 목록이다. 기존 탐지 응답이 요구하는 위치 좌표를 제공하지 않는다. 위치를 표시하는 화면이나 API 계약을 바꾸기 전에 요구사항을 확인해야 한다.
- 다음 시험은 사람 검수 사진에서 기기 식별을 재평가하고, 추천 설명의 기기 일치와 긍정·부정 반전을 원문과 대조한다. 이번 PR은 비교와 판단 근거를 기록한다.

## 실행과 재현 조건

- 현재 방식은 SAM 3에 점수 하한 0.35를 적용했다. EXAONE 3.5 7.8B Instruct AWQ(`f2699f35`)는 기존 vLLM 게이트웨이의 후보별 JSON 제약을 사용했다.
- 새 방식은 Qwen3-VL-4B-Instruct(`ebb281ec70b0`)를 NF4 이중 양자화, BF16 연산으로 적재했다. 사진은 최대 786,432화소 설정과 출력 200토큰 한도를 사용했다. 추천은 두 방식 모두 탐욕 디코딩, 출력 1,024토큰 한도, 첫 시도 기준이다. Qwen에는 프롬프트의 JSON 지시를 적용하고 출력 후 검증했다.
- 음성은 기존 Whisper large-v3-turbo CT2(`4df90f75`, int8_float16, 한국어)를 두 방식에 공통으로 사용했다. Qwen을 적재한 상태에서도 동일한 합성 전사문을 확인했다.
- Qwen 적재에 53.09초가 걸렸다. 적재 시간은 사진 지연 표에서 제외했다. 사진 34건의 첫 요청은 기존 방식 51.61초(모델 전환 포함), 새 방식 12.92초였다. 추천 표도 첫 요청을 포함한다.
- 메모리 샘플은 `nvidia-smi`에서 9,728 MiB 파티션 행을 골랐다. 최초 모니터가 다른 행을 읽어 모델 적재 도중에 측정을 바로잡았다. 아래 최대값은 올바른 행의 유효 샘플 기준이다.
- Qwen 실험 중 STT와 함께 관측한 GPU 사용량은 최대 5,107 MiB였다. 원복과 기존 구성의 혼합 입력 재생 구간은 최대 8,107 MiB였다. 측정 구간의 길이는 서로 다르다. 배치 1, 직렬 요청 조건이다. 운영 동시 부하와 장시간 안정성은 미측정이다.
- Qwen 실행 환경은 Python 3.10.14, PyTorch 2.7.1+cu118, Transformers 4.57.1, bitsandbytes 0.48.2였다. 후보 입력 `prompts_e35_kb21.json`의 SHA-256은 `4685f2a32d918e84a4dc9c4b3be18ee9b9959369fb5b73189a36216c5c3e4f6a`다.
- 실험 종료 시 셸 스크립트 끝의 Windows 줄바꿈으로 종료 코드 오류가 발생했다. 두 모델의 응답 파일과 복구 로그를 확인했고, 재현 스크립트의 줄바꿈을 수정해 `bash -n`으로 확인했다.
- 실험 순서와 원본 결과는 Cloud 작업 폴더 `~/safet/experiments/261119_ab/`에 있다. `baseline.py`로 STT와 사진 기준선을 측정하고, `compare.py exa`와 `compare.py qwen`으로 후보별 응답을 기록했다. 혼합 입력의 기존 방식은 `finish.py`로 한 번 재생했다. 기존 서비스 모드와 실제 음성·추천 호출을 복구 후 확인했다.
