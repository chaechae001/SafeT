# 로컬 사업장·평가표 전체 흐름 검수

검수일: 2026-11-18. `safet_local_review` 전용 DB와 현재 통합 폴더를 사용했습니다.
실제 AI 주소와 키는 검수 실행기에서 차단했으며, `catalog_v1` 기준 계산만 사용했습니다.
기존 평가표는 보존하고 별도 합성 사업장·평가표로 검사했습니다. 커밋·푸시하지 않았습니다.

## 발견한 문제와 수정

사업장 수정 화면을 연 직후 기존 정보가 도착하기 전에 입력하면, 늦게 도착한 기존 이름·기기 목록이 입력을 덮어쓸 수 있었습니다.
`frontend/js/workplace.js`에서 수정 정보를 불러오는 동안 사업장명·기기 추가 입력과 추가 버튼을 비활성화하도록 수정했습니다.
로딩 완료 후 입력 가능하고, 저장 오류가 나면 입력을 유지한 채 다시 저장할 수 있습니다.
API·DB 구조·위험도 기준 변경은 없습니다.

재발 방지를 위해 `backend/unit_tests/browser_workplace_edit_smoke.py`를 추가했습니다.
응답 전 입력 차단, 저장 오류 후 수정 이름·기기 보존, 재시도 성공을 브라우저에서 검사합니다. 실제 DB·AI·외부 서버를 호출하지 않습니다.

## 직접 확인한 결과

| 검수 항목 | 결과 |
|---|---|
| 사업장 등록 | 화면에서 사업장명·업종·튀김기 등록 성공 |
| 사업장 수정 | 이름 변경·작업대 추가 저장 성공 |
| 사업장 수정 로딩 | 기존 응답 도착 전 입력 차단 확인 |
| 사업장 저장 오류 | 모의 503 응답에서 기존 DB와 입력 보존, 재시도 성공 |
| 평가표 작성 | 새 사업장·참여자·텍스트 입력으로 기준 초안 생성 |
| 생성 응답 유실 | 서버 생성 후 응답만 끊고 재시도해 동일 번호 반환, 중복 생성 없음 |
| 평가표 저장 오류 | 모의 503에서 DB 무변경·체크 상태 보존, 재시도 성공 |
| 위험도 저장 | 현재 상 / 예상 중 저장 확인 |
| 실제 동시 저장 | 같은 버전으로 서로 다른 예정일을 동시 요청. 하나만 200, 나머지는 409. 성공한 데이터와 버전 유지 |
| 오래된 화면 저장 | 충돌 안내, 다른 요청이 저장한 내용을 덮어쓰지 않음 |
| 충돌 후 복구 | 최신 내용을 다시 연 뒤 저장 성공 |
| 삭제 | 미확정 평가표가 휴지통으로 이동, 일반 조회 404 |
| 복원 오류 | 모의 503에서 휴지통에 남음, 재시도 가능 |
| 복원 | 삭제 전 상세 데이터 전체 일치, 조치·담당자·예정일·위험도 유지 |
| 브라우저 오류 | JavaScript 오류 없음 |

동시성은 로컬 API·DB에 동시에 실제 저장 요청을 보냈습니다. 503 및 응답 유실은 브라우저 요청 단계에서 의도적으로 발생시킨 오류입니다.
운영 DB 장애나 외부 AI 장애를 실제로 일으킨 시험은 아닙니다.

## 자동 검사

- 별도 테스트 DB에서 전체 자동 테스트: 183개 통과. 브라우저 입력 보존 수정은 아래 별도 검사로 검증했습니다.
- 신규 사업장 입력 보존 브라우저 회귀 검사: 통과.
- 필수 CPU 자체 검사: 3개 통과.
- contracts JSON 구문·변경 공백 검사: 통과.
- 의존 라이브러리의 기존 deprecated API 경고 1건은 있었지만 테스트 실패는 없습니다.
