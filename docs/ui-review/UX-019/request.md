# UX-019 요청 · 2026-11-22

## 요청 원문 (발췌)
> 현재 웹앱 프로젝트의 UI/UX 색감과 디자인을 Safe-T 서비스 성격에 맞게 전면 개편하고 싶어. … 레퍼런스 감각: 카닥·필라이즈처럼 정보 위계가 명확하고 카드/리스트/입력 흐름이 직관적인 모바일 UI … 위험도 표시: 상·중·하 위험도와 현재 조치/개선대책 구분이 한눈에 읽히도록
> 색감은 초록색이 너무 소규모 사업장 음식점과 안어울리는 거 같아. … Splash 도 추가하고, 랜딩페이지도 개선해줘. 내가 이전에 수정한 부분은 건들지말고 디자인이나 색감 같은 디자인 쪽 위주로
> 우선 1안으로 진행할게.

## 결정
- 1안을 골랐다: 파랑 주색 #2563EB, 주황 #FF6B1A는 로고·그림에만.
- 범위(사용자 선택): 배치·구성·문구·동작은 유지하고 외형(색·글꼴·모양)만 바꾼다. 시작 화면은 새로 꾸민다.
- Splash: 첫 진입 시 1회 약 1.5초(UX-016 후속에서 이미 이 동작이 있어 모양만 바꿈).

## 대상
공통 토큰(전 화면에 영향) + 핵심 화면 01 로그인·시작·가입, 03 내 평가표, 04 작성(기본·현장·기기), 05 초안(목록·상세), 06 확정.
07 서명 ~ 10 휴지통은 공통 토큰으로 색만 바뀌었다. 화면별 확인은 사용자 확인 뒤 다음 단계에서 한다.

## 여러 페이지에 미치는 영향 (AGENTS.md: 공통 CSS 변경 설명)
- `common.css` 토큰 값을 바꿔 모든 화면의 주색·바탕·글자색·모서리·버튼 기본색이 함께 바뀐다.
- 모든 페이지에 Pretendard 글꼴 링크(jsdelivr CDN)를 추가했다. CDN을 못 쓰면 시스템 한글 글꼴로 대체된다.
- 기본 글자 15px → 16px.

## 통과 조건
- 위험도 색(빨강·노랑·초록)이 문서 상태·버튼·안내에 쓰이지 않는다.
- 320·390px에서 가로 넘침이 없다.
- 기존 화면 검사(UX-017 20개)와 전체 흐름(생성 → 체크 → 확정 → 서명 → 다운로드)이 통과한다.
