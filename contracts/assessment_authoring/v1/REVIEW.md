# v3 최종 검토

## 수정한 불일치

| 항목 | 적용 |
| --- | --- |
| 문서마다 다른 모드 이름 | input_based로 통일 |
| 조립 함수의 LLM 호출 책임 혼재 | extract_analysis와 compose_assessment 분리, analysis_bundle 인자 명시 |
| 자료 원본 SHA와 작업 시작 SHA 혼동 | SOURCE는 원본, START_HERE는 계약 브랜치의 동일 SHA |
| 문헌 근거 2개 제한과 3개 예제 충돌 | Schema·예제 모두 최대 2개 |
| 법령 Schema 허용·검증기 무조건 거절 | 기본 빈 registry, 검수 registry 주입 시 ID/URL/시나리오 대조 |
| 독립 검사기의 계산표 중복 | 원본 policy 스냅샷 로딩, 저장소 MATRIX·카탈로그 일치 검사 |
| assert 기반 검증의 최적화 실행 누락 | 명시적 ValueError 검사 |
| 근거 문장·media·기기 ID 연결 누락 | 원문 인용·ID·자료 유형 검사 |
| 부분/전체 미매칭 계약 누락 | assessment Schema와 예제 2세트 추가 |
| 기존 합의와 새 모드 혼동 | 기존 합의에 적용 범위 안내, 수동·과거 경로 유지 |

## 검증 범위

- 공통 계약: 33개 검사. 합성 예제 5개, 거절해야 할 변형 15개, 경계 4개, 등급표 9개.
- 동일 검사를 Python 일반 실행과 -O 실행에서 확인한다.
- reference/SOURCE.json의 자료 해시와 현재 저장소 카탈로그·MATRIX를 비교한다.
- AGENTS.md 지정 CPU self-test 3개를 실행한다.
- 실제 모델·GPU·API·서비스 종단 간 동작은 이번 문서/계약 PR의 검증 범위가 아니다.

합성 예제의 “전체 조건을 충족” 문장은 계산 계약 검사용이다. 실제 조치 해석 정확도나 현장 안전성을 입증하지 않는다.

## 구현 시 남은 확인

입력 어댑터·검색·추출·서비스 연결은 각 담당 구현 PR에서 완성한다.
추출의 부정/상충/복합 조건 해석, 법령 시행일·적용 조건 검수, 모델 토큰/지연, 저장·PDF 일치는 해당 구현에서 확인한다.
