# 화면 동작과 API 호출

공통 API 호출은 `api.js`, 화면별 동작은 `basic.js`처럼 화면 이름으로 구분합니다.

- API 주소·오류 처리는 공통 파일에서 관리합니다.
- API 키·DB 비밀번호를 프런트엔드에 넣지 않습니다.
- 입력 단계 간 상태와 실제 DB 저장을 구분합니다.
- 실제 JavaScript 파일은 화면 뼈대 구현 때 추가합니다.

## jQuery 연결 (2026-11-16 추가)

jQuery 3.7.1을 `vendor/jquery-3.7.1.min.js`에 로컬 파일로 두었습니다(인터넷 없이도 동작). SHA-256 `FC9A93DD…F0B1A`로 공식 배포본과 같은지 확인했습니다.
각 화면은 `jquery → common.js → 화면 JS` 순서로 불러옵니다.

| 파일 | 역할 |
|---|---|
| `common.js` | 화면(view) 전환·뒤로 가기, 확인 창, 입력 검사(칸 아래 오류), 날짜 입력·달력, 알림, 원형 로딩, 진행률 |
| `write.js` | 01 기본정보 참여자 추가·삭제, 02 현장 사진·최소 입력 검사, 04 초안 생성 진행률 |
| `draft.js` | 초안 리스트·입력 필요 건수, 위험 상세·입력 필요 모드, 현재 조치·대책 체크, 직접 추가, 초록 항목 탭, 일괄 지정, 키워드 추가, 저장·확정 |
| `workplace.js` | 업종별 기기 목록, 직접 추가(중복 합침), 사업장 수정·삭제 |
| `home.js` | 탭·기간·사업장 거르기, 10개씩 목록, 다녀오면 상태 복원 |
| `login.js` · `sign.js` · `share.js` · `trash.js` | 인증 요청·가입 검사 / 서명 칸(canvas)·저장 조건 / 링크 복사·공유 중지 / 영구 삭제·복원 |

### 공통 사용법 (`window.SafeT`)

- `SafeT.go('v-risk', opts)`: 같은 파일 안의 화면으로 이동합니다. 도착한 화면에 `safet:show` 이벤트로 `opts`가 전달됩니다.
- `SafeT.openModal('confirm')` / `SafeT.closeModal()`: 확인 창을 열고 닫습니다. `[data-close]`·Esc·바깥 클릭으로도 닫힙니다.
- `SafeT.confirm({ title, message, ok, cancel, alt })`: 브라우저 `confirm()` 대신 쓰는 확인 창입니다.
- 폼 제출: `required`·이메일·`minlength`·날짜 형식을 검사합니다. 화면별 추가 검사는 `safet:validate`, 제출 처리는 `safet:submit` 이벤트에서 합니다.
- `SafeT.toast()`, `SafeT.loading(true|false)`, `SafeT.runProgress()`: 알림, 원형 로딩(데이터만 저장), 진행률(AI 판단 포함)을 표시합니다.
- `[data-todo="안내 문구"]`: 아직 API가 없는 버튼에 붙이면 누를 때 안내 문구가 뜹니다.

### 아직 API 연결 전인 부분

- 화면의 평가표·사업장·위험 항목은 각 JS 파일 위쪽의 합성 예시 데이터입니다. 새로 고침하면 처음 상태로 돌아갑니다.
- 저장·AI 판단·진행률은 일정 시간 뒤 완료되는 데모입니다. API를 연결하면 서버 응답 시점에 맞춥니다.
- 판단 필요 항목의 '다시 판단'은 "예시 결과"라고 표시된 데모 값으로 채웁니다. 실제 AI 판단이 아닙니다.
- 음성 녹음, 엑셀·PDF 다운로드, 비밀번호 재설정, 공유 링크 재발급은 안내 문구만 띄웁니다.

## 백엔드 API 연결 (2026-11-16 추가)

- `api.js`: 공통 API 호출. 주소는 화면과 같은 호스트의 8001번 포트입니다(예: `http://127.0.0.1:8001`). 바꾸려면 `api.js`보다 먼저 `window.SAFET_API_BASE`를 정합니다.
  - `SafeT.api.post(경로, 본문)` / `SafeT.api.get(경로)`는 jQuery Deferred를 돌려줍니다.
  - 실패하면 `{ status, code, message, field? }`로 바꿔 줍니다. 서버가 꺼져 있으면 `code: 'NETWORK'`입니다.
- 연결된 화면: 회원가입(`login.html#v-signup`) 하나입니다. 나머지 화면은 아직 합성 데이터를 씁니다.
  - 인증 요청 → `POST /auth/signup/code`: 버튼에 60초 재요청 카운트다운을 표시합니다.
  - 6자리를 다 넣으면 → `POST /auth/signup/code/verify`: 자동으로 확인하고, 틀리면 칸 아래에 (n/5)를 표시합니다.
  - 가입하기 → `POST /auth/signup` → 사업장 첫 등록(`workplace.html?first=1#v-new`)으로 이동합니다.
- 확인하려면 화면 서버(8000)와 API 서버(8001)를 둘 다 켭니다. API 서버 실행 방법은 [backend/README.md](../../backend/README.md)에 있습니다.
- 화면 서버 주소로 열어야 합니다. 파일을 더블클릭해서 열면(`file://`) API가 허용 주소(CORS)에 없어 막힙니다.

### 가입 완료 후 이동 변경 (2026-11-16)

- 가입을 마치면 로그인 화면으로 이동합니다. "회원가입이 완료되었습니다. 로그인해 주세요." 안내를 띄우고, 이메일 칸에 가입한 이메일을 채웁니다.
- 위의 "가입하기 → 사업장 첫 등록으로 이동"을 이렇게 바꿨습니다.
- 화면설계서 07쪽(가입 직후 B02)과 다릅니다. 로그인 기능이 아직 없어서 가입 직후에는 로그인된 상태가 아니기 때문입니다.
- 로그인한 뒤 등록된 사업장이 없으면 사업장 등록(B02)으로 보내는 규칙(07쪽)은 로그인을 만들 때 반영합니다.

### 로그인 연결 (2026-11-16)

- 로그인(`login.html#v-login`) → `POST /auth/login`
  - 사업장이 있으면 내 평가표(`home.html`)로 이동합니다.
  - 없으면 새 사업장 등록(`workplace.html?first=1#v-new`, 취소 버튼 없음)으로 이동합니다.
- 토큰은 `sessionStorage`에 보관합니다(`SafeT.auth.token()` / `user()` / `save()` / `clear()`). `SafeT.api` 요청에는 `Authorization: Bearer` 헤더가 자동으로 붙습니다.
- 로그인 화면을 열면 이전 로그인이 끝납니다(토큰 삭제). 메뉴의 '로그아웃'도 이 화면으로 오므로 로그아웃이 됩니다.
- 로그인에 실패하면 비밀번호 칸 아래에 안내하고 비밀번호 칸을 비웁니다.
- 다른 화면들은 아직 로그인 여부를 확인하지 않습니다(합성 데이터로 화면 흐름 확인 가능).

### 로그인 확인 · 로그아웃 · 만료 후 복구 (2026-11-16)

바로 위 항목("다른 화면들은 아직 로그인 여부를 확인하지 않습니다")은 이제 맞지 않습니다. 아래처럼 바뀌었습니다.

- **로그인 확인:** `<body data-auth-required>` 화면 8개는 로그인해야 볼 수 있습니다(`home`, `workplace`, `trash`, `write`, `draft`, `result`, `sign`, `share`).
  - 로그인하지 않았으면 `login.html?required=1`로 보냅니다. 로그인하면 열려던 화면으로 돌아갑니다.
  - 토큰이 있어도 `GET /auth/me`에서 401이 나오면(위조·무효) 로그인 화면으로 보냅니다. API 서버가 꺼져 있으면 화면은 그대로 둡니다.
  - 로그인 확인 전에는 화면 내용을 숨깁니다(`body.auth-ok`).
  - `share-download.html`(받는 사람 화면)과 `login.html`은 로그인 없이 열립니다.
- **로그아웃:** 메뉴의 '로그아웃' → "로그아웃할까요?" 확인 → 토큰을 지우고 `login.html?logout=1`(안내 표시)로 갑니다.
  - 초안 화면에 저장하지 않은 수정이 있으면 "저장하지 않은 수정이 있어요"로 먼저 알립니다(설계서 08쪽). 화면은 `SafeT.hasUnsaved()`로 알려 줍니다.
- **만료 후 복구:** 토큰 만료 시각이 되거나 API가 `TOKEN_EXPIRED`를 돌려주면 보던 화면 주소를 저장하고 `login.html?expired=1`로 갑니다.
  - 화면별 편집 내용은 `SafeT.auth.onExpire(fn)`로 저장하고, 다시 로그인한 뒤 `SafeT.auth.takeRestore('화면')`으로 되살립니다.
  - 지금은 초안 확인(`draft.js`)만 편집 내용을 되살립니다. 위험 항목 체크, 보던 항목·목록 필터가 대상입니다.
- 팀원이 화면을 보려면 이제 API 서버와 DB를 켜고 회원가입·로그인을 해야 합니다.

### 사업장 관리 연결 (2026-11-16)

- `workplace.html`의 목록·등록·수정·삭제가 실제 API와 연결되었습니다(`workplace.js`). 이 화면의 합성 데이터는 지웠습니다.
  - **목록:** 사업장명 · 업종, 수정, 더보기(보유 기기), 삭제
  - **삭제:** "사업장을 삭제할까요?" 확인 창을 띄웁니다. 작성 중 평가표가 있으면 그 수도 안내합니다.
  - **등록:** 업종 목록은 DB에서 불러옵니다. 업종을 고르면 그 업종의 기기를 미체크로 불러오고, 업종을 바꾸면 체크와 직접 추가를 초기화합니다.
    저장하면 내 평가표로 이동합니다. 기기 목록을 못 불러오면 다시 불러오거나 직접 추가로 계속할 수 있습니다.
  - **수정:** 업종은 잠겨 있고, 사업장명과 기기만 바꿉니다. 저장하면 목록으로 돌아갑니다.
- `SafeT.api`에 `put()`, `del()`을 추가했습니다. 204처럼 본문이 없는 성공도 성공으로 처리합니다.
- 아직 합성 데이터인 곳: 내 평가표 사업장 선택, 새 평가표 01 기본정보 사업장 선택·03 보유기기.

### 내 평가표 연결 (2026-11-16)

- `home.html`이 실제 API와 연결되었습니다(`home.js`). 이 화면의 합성 데이터는 지웠습니다. 위 항목 중 "내 평가표 사업장 선택"도 이제 실제 데이터입니다.
  - **목록:** `GET /evals`(탭·기간·사업장·10개씩)
  - **사업장 선택:** `GET /workplaces`(사용 중인 사업장만). 저장해 둔 사업장이 삭제되었으면 '-전체-'로 바꿉니다.
- **카드:** 평가 이름, 상태, 사업장 · 평가일 · 작성자가 나옵니다.
  - 왼쪽 버튼: 작성 중 = '서명하기 · 확정 후'(비활성), 확정 = '서명하기 n/m', 서명 완료 = '결과 공유'
  - 카드를 누르면 작성 중은 `draft.html?eval=번호`, 확정은 `result.html?eval=번호`로 갑니다. 두 화면은 아직 이 번호를 쓰지 않고 합성 데이터를 보여 줍니다.
- 빈 값(사업장 '-전체-', 빈 기간)은 요청에 넣지 않습니다.
- 늦게 도착한 이전 응답이 화면을 덮지 않게 했습니다. 불러오지 못하면 다시 불러오기 버튼을 보여 줍니다.
- 엑셀 다운로드는 아직 안내 문구만 보여 줍니다.
